# 3.0.0-WP06g3 — the real-hardware fix batch (ocse_enc_fix)

The postmortem batch: seven real-machine disasters from the WP06g2
field test, root-caused byte-by-byte and fixed.  Plus the recovery
environment on every path, and the original g3 goal (the OCSE/OCIRE
encoding repair).

## What changed

- **Disk probing matches real PCs (4.1).** The AHCI probe no longer
  matches a single exact PCI class code: RAID/RST-mode SATA
  controllers (class 0x0104, the factory default on many brand
  machines) are visible now, alongside the classic 0x010601.  NVMe
  gained timeout retries and a disable-CC rewrite on the real-hardware
  tolerance path.  And the probe is no longer a black box: every AHCI
  and NVMe controller event logs to the **serial line** (the q35+AHCI
  battery shows 8 `ahci:` lines on serial where the old kernel showed
  zero).
- **`serial_encoding utf8|gbk` (4.2).** The kernel serial output is
  UTF-8 by default and converts to GBK on demand - Chinese serial
  tools (GBK by convention) render `lang zh` cleanly now.  OCSE's
  `ocse_out` rides the same standard (one policy, not two).
- **The VMware boot crash (4.3).** The OCBL real-mode stack tops at
  0x8E000 now (below every observed EBDA), and the boot-state monitor
  reads the BDA 0x40E EBDA base and disables its state area when a
  large EBDA would overlap it.  Awaits the user's real-machine
  confirmation.
- **OCIRE on every path (4.4).** The main ISO carries
  `/boot/ocire.elf`; the OCBL menu scans and lists "OCIRE recovery";
  the installer writes a **dedicated recovery partition** (a fresh
  carve from the disk's unallocated tail, FAT32, with the recovery
  kernel streamed onto it - the streamed copy landed this batch after
  the zh font growth exposed the fixed-buffer read).  The installed
  disk boots with both entries.
- **The editors are actually localized (4.5).** The 21 hardcoded
  English UI strings in the shared editor core route through `tr_()`;
  the nano legend, prompts and shortcuts are Chinese under `lang zh`.
- **A real IME preedit buffer (4.6).** Pinyin never enters the text:
  it composes in a preedit strip rendered on the status bar (with the
  candidates and the IME state), and a failed IME service call
  reports instead of silently passing letters into the file.
- **Differential rendering (4.7).** The nano bar pins to the last row
  via ANSI positioning and repaints only what changed: the measured
  keystroke stream carries **zero** newlines per letter (the
  postmortem measured 3 scrolled lines per keystroke, 8 full-bar
  prints per session).
- **OCSE/OCIRE encoding repair (4.8, the original g3 goal).** The
  em-dash mapping (GB2312 0xA1AA vs U+2014) that broke whole-string
  conversion is fixed on both the OCSE tables and the main-kernel
  font blob; OCIRE gained the hanzi font, UTF-8 decode and the zh
  strings (its "mojibake" was missing capability).  The zh-capable
  ocire.elf is 6x larger - see the streaming installer fix above.
- **Tooling (4.9).** The release boot gates match the live serial
  banners again; the "branches: ain]" CI-workflow leftover turned out
  to be a terminal-transcription phantom (a literal `[m` eaten as an
  ANSI reset) - audited byte-level, retired from KNOWN_ISSUES.
- **Kernel-window diet.** The nine ~16-18 KiB static TLS record
  buffers moved to the heap (the identity window had closed to 24
  KiB; the CI's gcc-13 crossed it).  HTTPS e2e 7/7 on the dieted
  kernel.
