Live-caught traps fixed on the way (all reproduced -> root-caused -> fixed -> re-verified):
1. xorriso -as mkisofs has no -boot-load-seg and SeaBIOS maps El Torito load_seg=0 to 0000:0x7C00
   (same entry form as an MBR) - stage1 rewritten around the 0x7C00 base + entry-form check.
2. -boot-info-table zeroes boot-image bytes 8..0x47 (ISOLINUX/GRUB convention; their images keep
   the first 72 bytes free) - it silently destroyed stage1's entry code.  OCBL does not need its
   LBA (BIOS preloads the whole image), the option is OFF and the reason documented in the ISO
   script.  Found via a minimal UART boot sector that flooded the serial line with 5 MB of zeros.
3. build_test_iso.py was not a make prerequisite - the fixed script never ran (stale ISO);
   same dependency class as WP-02 F5.  Script now a hard dep.
4. The PE switch left the segment registers at their real-mode values (DS=0x07C0 is beyond
   the GDT limit) - the first DS-relative access in the core faulted.  core_head loads flat
   data segments as its very first instruction group.
