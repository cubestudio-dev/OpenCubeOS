# Open Cube OS 3.0.0-WP05 OCBL - B5-7: GRUB removed, OCBL everywhere
==============================================================
Test: the RELEASE pipeline (make all) with the GRUB chain deleted:
      tools/build_iso.sh now stages the dual-firmware OCBL pair and
      packs through the OCBL ISO packer; the SAME build/opencube.iso
      boots under SeaBIOS AND OVMF, and the OCBL scanner registers
      the ISO itself as the OCOS boot target ("Open Cube OS (cd0)").
Date: 2026-10-31 UTC  qemu 10.0.13  SeaBIOS 1.16.3 + OVMF 2025.02

GRUB removal ledger (the WP-05 spec hard requirement):
  REMOVED            grub.cfg, grub-ab.cfg (the GRUB menus)
  REMOVED            ocire/grub-ocire.cfg (the OCIRE ISO menu)
  REMOVED            iso/ tree (boot/grub/fonts/unicode.pf2 + stage dir)
  REWIRED            Makefile KERNEL_ISO: depends on the OCBL pair,
                     not grub.cfg; iso: -> tools/build_iso.sh (OCBL)
  REWIRED            tools/build_iso.sh: GRUB-mkimage/xorriso pipeline
                     -> the OCBL packer (dual El Torito + ESP + G13)
  REWIRED            tools/build_ocire_iso.sh: same swap (B5-7)
  REWIRED            ocire/ocire.mk: ISO deps -> the OCBL pair
  REWIRED            tools/make_update_pkg.sh: the update package no
                     longer carries boot/grub.cfg (there is no loader
                     config left to update); ota_ab.c still ACCEPTS
                     packages that carry it - older releases stay
                     upgradable.
  SCANNER            judge_volume: the OCSE marker now judges FIRST;
                     the ISO gate on OCOS/OCIRE opened - the release
                     ISO self-registers as "Open Cube OS (cd0)" and
                     the OCIRE recovery ISO as "OCIRE recovery (cd0)".
  DECLARED BOUNDARY  embed_grub.py / kernel-internal grub_boot_data:
                     the WP-10d rule-9 INSTALLER payload (abdisk /
                     install / grub-install write a boot image from
                     inside the running OS).  It is NOT a boot-time
                     GRUB path - no boot ever goes through it - and
                     the disk-install chain belongs to the upcoming
                     installer work packages.  Untouched, declared.
  DECLARED BOUNDARY  ocire/grub-dual.cfg.in + tools/make_ocire_disk.sh:
                     the WP-02 dual-boot DISK generator (a development
                     fixture).  Same installer-domain boundary.

Build gates: make all RC=0 - kernel ELF 2,077,472 B (baseline-exact
byte size), opencube.iso 3,639,296 B (GRUB-free: the 12.3 MiB GRUB
modules+font ISO shrinks to 3.5 MiB), OTA package without the
grub.cfg member, OCBL dual-firmware pair inside.

  - Under OVMF the optical drive enumerates as BlockIo "hd0" (whole-
    disk index naming); under SeaBIOS the same ISO is cd0/0xE0 - the
    six-class scanner labels the class correctly on both sides.
  - QEMU monitor key injection never reaches OVMF's ConIn on big
    fleets (BDS probes every disk first); the acceptance flows ride
    the spec's default-entry auto-load path, and the three-key
    contract is regression-proven on the BIOS flavor (above) exactly
    as in the B3 evidence.  No OCBL change involved - the UEFI flavor
    polls ReadKeyStroke continuously (50w+ calls per menu window).
