## 1. Contract

Every interface below has:

1. a header declaration with a doc comment,
2. a default implementation in the kernel (no stubs),
3. a test that exercises it (`chinesetest` 91 checks in-kernel +
   tools/wp10_chinese_e2e.py 14 checks per boot mode),
4. this document.

## 2. Font interfaces (chinese/chinese_font.h)

| Interface | Purpose | Default impl |
|---|---|---|
| `chinese_font_init()` | init the slot registry + load the embedded font into slot 0 | chinese/chinese_font.c |
| `chinese_font_shutdown()` | drop runtime slots, reset counters | chinese/chinese_font.c |
| `chinese_font_load()` | idempotent "ensure embedded font loaded" | chinese/chinese_font.c |
| `chinese_font_load_mem()` | register a runtime font from memory (name + glyphs + uto table) | chinese/chinese_font.c |
| `chinese_font_unload(slot)` | unload a runtime slot (slot 0 rejected) | chinese/chinese_font.c |
| `chinese_font_lookup(slot, zone, wei)` | GB2312 zone/wei -> compact glyph index (bit15 = symbol table) | chinese/chinese_font.c |
| `chinese_font_lookup_unicode(slot, cp)` | Unicode BMP -> compact glyph index (binary search) | chinese/chinese_font.c |
| `chinese_font_get_bitmap(slot, idx)` | compact index -> 32-byte bitmap | chinese/chinese_font.c |
| `chinese_font_get_bitmap_unicode(slot, cp)` | Unicode -> bitmap in one step | chinese/chinese_font.c |
| `chinese_font_get_metrics(w, h, stride)` | 16 x 16, stride 2 | chinese/chinese_font.c |
| `chinese_font_index_to_unicode(slot, idx)` | compact index -> Unicode (GB2312 decoding) | chinese/chinese_font.c |
| `chinese_font_status(out)` | stats snapshot (counts, sizes, counters) | chinese/chinese_font.c |

Font data: `chinese/chinese_font_data.c` (AUTO-GENERATED by
tools/gen_chinese_font.py from GNU Unifont; 6763 hanzi = 216,416 B +
682 symbols = 21,824 B, zone slot tables + a 7445-entry sorted
Unicode reverse map + an index->Unicode table).

fix1 session-safety APIs (tui/ core, added by WP-10-chinese_support-fix1:
the window pool, the text-layer focus/status caches and the CSI decoder
are session state - they are reset by `tui_init`/`tui_shutdown` so a new
session never inherits drained pools or half-finished escape sequences):

| Interface | Purpose | Default impl |
|---|---|---|
| `tui_windows_reset()` | free every window + empty the 16-slot pool (slots are reused after `tui_window_free`) | tui/tui_win.c |
| `tui_text_reset()` | drop the cached focus/status-window pointers | tui/tui_text.c |
| `tui_input_reset()` | reset the CSI decoder + mouse pending state | tui/tui_input.c |

IME data: `chinese/pinyin_data.c` (AUTO-GENERATED by
tools/gen_pinyin_table.py from pypinyin; tone-free readings of the
GB2312 level-1 set, unicode-sorted map, binary-searchable).

TUI wide-cell protocol: `tui_cell_t.ch` is u32 and carries the
codepoint; the cell RIGHT of a CJK glyph carries `TUI_WIDE_CONT`
(0xFFFFFFFF). The fb backend draws the 16x16 bitmap at the left cell
and paints the continuation cell with the cell background; the serial
backend emits real UTF-8 and skips continuation cells.

## 8. Related surface changes

- `drivers/display/screen_console.h/.c`: **additive only** - new
  `screen_console_scroll_up()` (scroll without moving the cursor, used
  by the cn write path). The stock putc state machine is untouched.
- `drivers/display/screen_serial_in.c`: 8-bit bytes (>= 0x80) are now
  forwarded to the keyboard queue biased by +0x100 so pasted UTF-8
  reaches the line editor; the 0x80-0x9B OC_KEY_* range cannot
  collide.
- `shell/shell_lineedit.c`: UTF-8 character boundaries for
  backspace/delete/left/right/Ctrl+W, display-width redraw, and the
  0x100-0x1FF byte input branch. For pure-ASCII lines the emitted byte
  stream is identical to the previous implementation.
- `shell/shell_cmds_file.c`: `cat` outputs through
  `console_cn_puts_enc(..., ENC_UTF8)` - ASCII files stay
  byte-identical, UTF-8 files show real CJK glyphs.
- `tui/tui.h`: new `TUI_WIDE_CONT` marker.
- `tui/tui_text.c`: `tui_print` decodes UTF-8; `tui_addch` writes wide
  glyphs as a left cell + TUI_WIDE_CONT pair. Pure-ASCII strings keep
  the old byte-per-cell path.
- `tui/tui_core.c`: fb backend draws 16x16 CJK glyphs and handles the
  continuation cell; serial backend emits real UTF-8.
- `shell/shell.c`: `g_wp_order[]` gains the WP-10-chinese_support tag.
- `kernel/main.c`: render_chinese_init() + console_cn_init() after
  console init; chinese_cmd_register() after tui_cmd_register().
- `Makefile`: `chinese` added to KERNEL_DIRS.
- `tools/run_fix4_regression.py`: command-count baseline 213 -> 222
  (additions only) + the chinese_support describe form accepted.

## 9. Tests

- `chinesetest` (in-kernel, 91 checks): font data (counts/sizes/all
  bitmaps non-empty), font lookup (zone/Unicode both directions,
  round-trip, gap slots), font management (load/unload/runtime
  slot/unload-slot-0 rejection), GB2312 codec (decode/encode/invalid/
  truncated), UTF-8 codec (strict rejects + 4-byte + encode round
  trip), conversion (GB2312<->UTF-8), detection (ASCII/UTF-8/GB2312/
  empty), renderer (widths/registry/active cell/draw paths), console
  extension (encoding switch/putcw columns/display width), line
  editing (ASCII unchanged + CJK backspace/delete/LEFT/insert), font
  engine registry (register/select/unregister), TUI Chinese
  (str-cols/IME resolution/print/menu+form validation), VFS UTF-8
  file (write/read through the real VFS for the E2E `cat`).
- `tools/wp10_chinese_e2e.py <iso> bios|uefi`: 17 checks per mode on a
  live boot - status commands, chinesetest ALL PASS, font listing,
  font-test, encoding/encoding-test, ime/ime-test, tui-cn open+quit
  (shell alive), `cat /tmp/cn.txt` carrying real UTF-8 bytes over the
  serial echo path, help -w tag, command count 222, uname - plus the
  fix1 input-path checks: `ime -i` composes 你 over the console with
  real keystrokes, the launcher's 中文输入 pad composes 你
  (n i 1 -> Enter), and tui-cn enter/quit/re-enter still renders
  (pool reuse).
- fix1 (WP-10-chinese_support-fix1) regression blocks: `chinesetest`
  blocks [13]/[14] (ASCII editor "home" verbatim, IME pad and console
  IME compose 你, digits land verbatim, Esc cancels) and the
  `tui-test` fix1 block (injected key immediate, empty queue blocks
  the full budget, 40 new/free pool cycles, Esc maps through
  OC_KEY_ESC_KEY, serial double-ESC delivers Esc). The serial CSI
  decoder only treats "ESC [" as a control sequence - any other byte
  after ESC is a plain keypress, so "ESC ESC q" (leave a page, then
  quit) can no longer swallow the q.
- `tools/wp10_chinese_shot.py`: screendump + pixel verification
  (font-test 4/4 CJK glyph blocks; tui-cn Chinese page title pixels).
- Regression gates re-run on the final tree: TUI E2E 32/32 x2, full
  regression 28/28 (baseline 222), dhtest 5/5, SSH E2E 5/5, HTTPS E2E
  7/7, host suite 17/0/2.
