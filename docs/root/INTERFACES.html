Open Cube OS Interface Reference (2.1.0) ​

Every entry below is extracted from the real tree at generation time: the L0 command declarations straight from the OC_SHELL_CMD call sites, the ring-3 surface from the ush SVC_CMDS table and services/l1/l1svc_defs.h, the kernel-side declarations from the service headers. Regenerate with make api-docs.

  • v1.0.0 commands (compatibility baseline): 233 - all mapped below, none dropped
  • 2.1.0 command homes: 251 total = 99 in the L0 recovery shell + 133 ring-3 SYS_L1SVC ops + 19 ush built-ins
  • L1SVC service surface: 17 categories / 158 numbered ops
  • Kernel-side declarations across the service headers: 144
  • Syscalls: 54 (grep -c '#define SYS_' core/core_syscall.h, SYS_L1SVC(110) added in 2.0.0)
  • Source lines: 130,572 across 379 files (README verification command; .c/.h/.S, generated data blobs excluded)

2.0.0 is a breaking re-architecture, stated precisely (2.1.0 correction of the over-general 2.0.0 phrasing): the three driver-family register hooks (driver_block_register, driver_nic_register, driver_snd_register) moved from the public v1 L1 headers into the per-family internal headers (services/*/drv_internal.h, 'internal since 2.0.0'); drivers and services now declare their identity in-file via OC_DRIVER_DECL / OC_SERVICE_DECL; every operational command class moved to the ring-3 service surface; and the only true deletions on the v1 numbered surface are the two entries in the deletion register (Part 2d). Other register-class declarations (tui_ext.h menus/pages/widgets/..., watchdog_register, signal_register, shell_register_builtin) are STILL PUBLIC in the v2 tree - the per-entry truth is Part 2c. What deliberately stays in L0: the kernel self-tests, the watchdog, the crash policy controls, the kernel log readers (dmesg/logcat/logctl/crashlog/dumpinfo/crashtest), the chipset diagnostics, the recovery-environment file commands, and the interactive session commands (ssh/sshd).

1b - Ring-3 service commands (ush, 133 SVC rows + 19 built-ins) ​

The default boot entry (ush, ring 3) routes these through SYS_L1SVC(110) to the owning L0 service; the built-ins run entirely in ring 3 (classic file/process syscalls) or through the SYS_NETCMD bridge (ifconfig, netstat, ping, wget).

Counting caliber (2.1.0, P-14): the ush SVC_CMDS table itself carries 142 rows. The 133 rows below are the unique names attributed to their first home: the 9 dual-homed names (halt, hpet, pmtimer, poweroff, reboot, rtc, shutdown, sleep, tsc) are registered BOTH as L0 recovery-shell commands and as ush SVC rows; the first-home rule counts them as L0 here, and they stay callable from both shells. 133 + 9 = 142 ush rows; the unique-name ledger (99 L0 + 133 SVC + 19 built-ins = 251) is unchanged by dual-homing.
