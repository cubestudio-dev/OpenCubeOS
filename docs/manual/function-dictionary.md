# Function dictionary — every command of Open Cube OS 3.0.0

This page is the complete, no-gaps index of the 3.0.0 user surface:
**311 commands = 300 registered programs + 11 ush built-ins**.
Every program below can be typed at the `ush>` prompt exactly as spelled
(it is in the kernel registry, `OC_USERPROGS[]`, generated by
`tools/gen_userprogs.py` from `ocos/l1apps/`).

Per-command details live in [commands/](commands/index.md) (293 pages, one
per command). This dictionary adds what those pages do not spell out next
to every entry: the **hidden syntax** — flags, subcommands and argument
forms that work but are not shown in the registry hint or in `help`.

## How to read this page

| Marker | Meaning |
|--------|---------|
| `⚑` | A **hidden argument surface**: the syntax works, but the registry hint, `help`, or the app's own usage line does not mention it (or mentions it only in a subcommand's `usage:`). |
| *(none)* | The command takes no arguments (or its arguments are fully advertised). |
| *destructive* | Destroys data; the wizards guard it with retype + bare-`y` confirmation, classic/direct dispatch runs it immediately. |

The 12 ush built-ins are summarized here and documented in full in
[ush-reference.md](ush-reference.md). Test/diagnostic stubs (~93 of the 300)
have their own deep page: [hidden-commands.md](hidden-commands.md).

## Where the surface comes from

- 276 historical commands are frozen by the regression gate
  (`tools/run_fix4_regression.py` measures the registry at ≥ 276; 3.0.0
  ships 300). Nothing can be silently removed.
- The 8 **mega-apps** were merged in 3.0.0 (`update`, `disk-tool`,
  `net-tool`, `sound-tool`, `files`, `sysdiag`, `hwinfo`, `power`); the
  historical single-command apps stayed registered, so every op has at
  least two spellings (see [mega-apps.md](mega-apps.md)).
- `ush` and `ld_so` are registered but were never v2.2.0 shell commands
  (tag `l1`).

### help — the three modes

```
ush> help            built-in summary + "Registry: 300 programs - 'help -a'
                     lists them all, 'help -w' groups by work package."
ush> help -a         built-ins + every registry entry, A-Z, tagged
ush> help --all      (same)
ush> help -w         built-ins + registry grouped by work package;
ush> help --wp       the mega group renders FIRST
```

`help -a` and `help -w` are the flags most users never find; the standalone
[help](commands/help.md) app accepts the identical flags. Row format is
`  name  [tag]  hint` (hint follows the live locale, zh falls back to en).

### The 19 category tags (from the generator's WP_TAGS, frozen)

| tag | n | tag | n | tag | n |
|-----|---|-----|---|-----|---|
| l1 | 35 | ush | 16 | camera | 10 |
| core | 25 | ota | 16 | usb | 9 |
| block | 24 | net | 16 | power | 8 |
| display | 22 | input | 18 | mega | 8 |
| nic | 20 | snd | 17 | recovery | 7 |
| fs | 20 | | | watchdog | 5 |
| | | | | time | 4, crypto | 4 |

Category tags are historical and deliberately quirky: ACPI/I2C/PCI/MSI
tools sit under `input`, SCSI/gameport/parallel/IR sit under `camera`,
`lspci` is `net`, `ssh`/`sshd` are `crypto`, `reboot` is `ota` while
`reboot_test` is `power`. Do not read semantics into the tags; they are
grouping aids only.

## mega (8) — the merged wizard apps

Every mega-app has **three doors**: no arguments → interactive wizard;
`<app> <op> [args]` → classic dispatch (byte-identical historical
output); `<app> direct <op> [args]` → verbatim passthrough. The literal
word `direct` is skipped and the rest reaches the historical op.

| Command | Purpose | Hidden / extended syntax |
|---------|---------|--------------------------|
| [update](commands/update.md) | OTA update wizard (5-step linear flow) | ⚑ `update direct` = bare online flow; ⚑ `update status` / `update --status` — A/B slot + version status (prints the `A/B disk: present` anchor); ⚑ `update --local <path>` / `update local <path>` — offline install from a package tar.gz |
| [disk-tool](commands/disk-tool.md) | disk / filesystem wizard | ⚑ `direct` passthrough over a 30-op verbatim table (block 23 + fs 7): ahci, nvme, ata, dskstat, lsblk, parted, mkfs.fat32, mkfs.exfat, mkfs.ext4, fsck, sync, ahci_test, nvme_test, ata_dma_test, virtio_blk_test, disk_rw_test, partition_test, fs_mount_test, real_hw_test, abdisk, install, grub-install, abcfg, mount, mounts, umount, fatmount, fatstat, tree |
| [net-tool](commands/net-tool.md) | network wizard | ⚑ `direct` over 16 ops: arp, dhcp, dns, dnstest, firewall, ip, lspci, nf_test, route, tcpcc_test, tcpstats, tcptest, ssh, sshd, wifi, bt |
| [sound-tool](commands/sound-tool.md) | audio wizard | ⚑ `direct` over 17 ops: sound, hda, ac97, sb16, es1370, virtiosnd, usbaudio, play, volume + the 6 driver selftests + audio_rw_test, sample_rate_test |
| [files](commands/files.md) | file manager wizard (the only fork/execve mega-app) | ⚑ `direct` launches real programs: ls, tree, df, du, cp, mv, rm, edit, stat, chmod |
| [sysdiag](commands/sysdiag.md) | system diagnostics wizard | ⚑ `direct` over 46 op rows (incl. the two-word spellings `health export`, `health watch`); crashtest is reachable through classic/direct ONLY — deliberately not a wizard button |
| [hwinfo](commands/hwinfo.md) | read-only hardware inventory wizard | ⚑ `direct` over 26 read-only ops (display/time/pci/acpi/usb/camera/input families) |
| [power](commands/power.md) | power wizard | ⚑ `direct` over 9 ops: shutdown, poweroff, reboot, halt, sleep, poweroff_test, suspend_test, halt_test, reboot_test |

The `direct` keyword is undocumented in every registry hint — it is
documented only in each app's `usage()` text. `update`, `disk-tool lsblk`
and `disk-tool direct lsblk` are three equivalent spellings of the same
service op.

## How an argument reaches its grammar

Most of the commands above are thin wrappers over a service op, and
the argument handling explains several behaviors users find
surprising:

- The standard app skeleton (`l1_api_syscall.h`, `l1svc_main`) joins
  `argv[1..]` with single spaces into one **256-byte argument line**,
  sends it with `sys_l1svc(cat, op, arg, out, 32768)`, and prints the
  result. So multi-word grammar (`firewall add in drop tcp port 22`)
  works exactly as typed — but everything past 256 bytes is lost.
- The output buffer is a static **32 KiB**. `help -a`'s full registry
  listing (~12 KiB) fits; the stack-truncated variant was a bug long
  fixed.
- On a non-zero rc the wrapper prints `<app>: service call failed (rc=-1)` — the shared template of ~150 of the 300 apps (the i18n
  key is shared by 250 apps total). When you see it, the real story is
  in `dmesg`: see
  [../troubleshooting/error-catalog.md](../troubleshooting/error-catalog.md)
  §7.1 for the unified triage.
- A few commands are NOT wrappers: `files` and `run` fork+execve real
  programs; `ush`, the editors, and the flat `l1` probes do their own
  syscalls.
- `dmesg` joins its argv WITHOUT spaces (a single token) — an oddity
  kept for historical compatibility: always `dmesg 100`, never
  `dmesg -n 100`.

## Command-name quirks

Frozen historical spellings worth knowing:

| Quirk | Explanation |
|-------|-------------|
| `edit` == `nano` | byte-for-byte the same face; `edit` is the v2.2.0 spelling |
| `shutdown` == `poweroff` | both spell the same power op |
| `rtl8168` prints `rtl8169: ...` internally | the driver family name; the command face is `rtl8168` |
| `mounts` == bare `mount` | both list; only `mount <type> <dev> <path>` mounts |
| `reboot` is tagged `ota`, `reboot_test` is `power` | frozen category tags, no semantics |
| `lspci` is tagged `net` | it shares the net-family op number |
| `ssh`/`sshd` are tagged `crypto` | the crypto service owns their ops |
| ACPI/I2C/PCI/MSI tools are tagged `input` | the historical "chipset/input" bucket |
| SCSI/gameport/parallel/IR are tagged `camera` | the legacy-ports bucket |
| `mkfs-fat32.md` in commands/ vs `mkfs.fat32` at the prompt | the docs tree avoids dots in filenames |
| `help` exists both as a built-in and an app | same 12 rows + registry count, same flags |

## What help does not highlight

- **None of the 35 hidden surfaces above appear in the registry hint.**
  `help -a` prints one hint line per program; subcommand grammars are
  visible only by running the command with a bad argument (most print a
  `usage:` line) or by reading [commands/](commands/index.md).
- The **test stubs** (~93 programs) are listed like any other command —
  nothing marks them as tests. They are safe to run but a few are
  deliberately disruptive (`crashtest`, the power-path probes,
  `stackovf`, `badapp`); see [hidden-commands.md](hidden-commands.md).
- The category tags in `help -w` are historical, not semantic (see the
  quirks note above).
- `fg`/`bg` appear in the built-in table but are **not implemented**
  (they print a refusal); `jobs` and `cmd &` are real.
- The hints themselves are bilingual (`_hint` key in each app's
  `i18n/{en,zh}.json`, consumed at build time); a missing translation
  is a build violation, so you never see a raw key as a hint.

## Discovering syntax at runtime

When you cannot reach this manual:

1. Type the command with a deliberately bad argument — most grammars
   print their `usage:` line (`crashtest x`, `watchdog x`, `logctl x`,
   `firewall x`, `config x`).
2. `help -w` to find the family, then the family's status command
   (bare invocation is almost always the status form).
3. The wizards double as syntax teachers: the questions they ask map
   1:1 to the positional grammar (net-tool's static-IP path asks
   address → mask → gateway in exactly the `ip <a> <m> <g>` order).
