# Internals: entropy and the crypto core

The RNG and the primitive families the protocols (TLS, SSH, the
OTA verifier) build on. Implementation:
`ocos/services/crypto/` - `interface/svc_crypto_{api,core,aead,bn, curve25519,ec_nist,rsa,sha512,x509}.h` and matching `src/`
modules, plus `src/svc_crypto_irq_window.h`,
`src/svc_crypto_roots.h` (generated),
`src/svc_crypto_dh_scale_vectors.h`. Usage:
`cryptotest` / `dhtest` (the L1 face IS the test face).

## 1. The DRBG (SP 800-90A HMAC_DRBG)

Header comment (verbatim intent): "BUG-0106 (A4-02) replaced the
old timer-seeded xorshift32 with an HMAC_DRBG (SP 800-90A):
RDRAND-seeded when the CPU offers it, RDTSC + boot-jitter
re-mixed otherwise, instantiated at first use and reseeded on
demand. The DRBG state is protected by the crypto IRQ window
(BUG-0294, A4-07) so concurrent kthreads can never observe the
same generated block."

Implementation facts:

- State: `static u8 drbg_k[32]; static u8 drbg_v[32]; static int drbg_ready;`
- `drbg_update` implements NIST SP 800-90A section 10.1.2:
  `K = HMAC(K, V || 0x00 || data); V = HMAC(K,V); if data: K = HMAC(K, V||0x01||data); V = HMAC(K,V)`
- Entropy gather `drbg_entropy32`: RDRAND (CPUID-checked,
  `rdrand %0 ; setc %1`) 8 bytes at a time; the fallback mixes
  `rdtsc_now()` and weak sources; the final xor with
  `rdtsc ^ (core_timer_ticks() << 1)` lands on bytes 24-31.
- **Why it matters** (the old xorshift32 was catastrophically
  weak): "past and future key the kernel ever generated is
  computable by a passive observer. Both the SSH server and the
  TLS client were effectively transparent."
- The RDRAND wrapper's `setc` flag is the u8/"=q" inline-asm
  constraint the stricter CI assembler forced into correctness -
  see [../dev/portability.md](../dev/portability.md).
- The **IRQ window** (`svc_crypto_irq_window.h`): a single-core
  save/cli/restore pair (`pushfq; popq %0; cli` /
  `pushq %0; popfq`) used by the lazy initializers (AES inverse
  S-box, NIST curve tables) so concurrent kthreads never observe
  the same generated block or a half-built table. Host test
  builds expand it to nothing (documented as a build-environment
  property - "NOT SMP protection and NOT a lock"; the kernel is
  single-CPU).

## 2. The primitive families

| Family | Members | Validation |
|---|---|---|
| Hash | SHA-256 (one-shot + streaming `crypto_sha256_ctx{u32 h[8]; u64 total; u8 buf[64]; int buflen;}`), SHA-384/512 | NIST vectors via `cryptotest` |
| MAC / KDF | HMAC-SHA-256 (RFC 2104), HKDF-Expand (RFC 5869), the TLS 1.3 key schedule (RFC 8446 section 7.1: `net_tls13_ks_expand_label` / `derive_secret`) | NIST vectors + RFC 8448 host tests |
| Symmetric | AES-128 block/CTR/CBC (FIPS-197), AEAD: AES-GCM, ChaCha20-Poly1305 | RFC 8439 vectors, NIST GCM TC3/4 (host harnesses) |
| DH | big-int modexp: fixed 1024-bit (`DH_BYTES 128`, Oakley Group 1, RFC 2409) + generic `crypto_dh_modexp_n` (SSH group 14 2048-bit); embedded `crypto_dh_group1_prime/generator`, `crypto_dh_group14_prime[256]` | python3 pow() goldens (the scale-sweep vectors) |
| RSA | `svc_crypto_rsa.c` (verify paths for TLS/SSH; `RSA_DEBUG` is a source-local `#ifdef`) | openssl fixtures (SKIP-FIXTURE harness) |
| Elliptic | NIST P-256 ECDH/ECDSA (`ec_nist`), X25519 (`curve25519`) | RFC 7748 vectors, P-256 KAT (host harnesses) |
| Certificates | X.509 parse + CA chain validation + SAN dNSName hostname check (`x509`) | live-site chain fixtures (host harness) |

The numbered L1 extension set "stays closed" for encoding
(Driver-API style extension); the crypto L1 surface is exactly 2
ops: `cryptotest` (op 1) and `dhtest` (op 2), both captured.

## 3. The embedded root CA store

`src/svc_crypto_roots.h`: "Auto-generated by tools/embed_roots.py
- DO NOT EDIT BY HAND. Embedded root CA store (DER) for the
X.509 chain validator." Raw DER byte arrays (an 809-line file)
covering the public roots - e.g. `root_isrg_root_x1[]` (ISRG Root
X1, 4096-bit RSA, valid 2015-06-04 -> 2035-06-04), plus the ISRG
X2, GlobalSign, GTS R1/R4, DigiCert, Baltimore, Amazon, Microsoft,
Sectigo E46/R46 roots. The TLS client verifies server chains
against this store; a self-signed chain is REFUSED by default
(`config set tls.insecure 1` is the explicit opt-in - HTTPS E2E
check 0).

## 4. The consumers

- **TLS client** (`services/net/src/svc_net_tls.c`): TLS 1.3
  (X25519 + AES-128/256-GCM + ChaCha20-Poly1305, full HKDF key
  schedule, encrypted handshake, CertificateVerify) and TLS 1.2
  (ECDHE_RSA AES-GCM 0xC02F/0xC030, ChaCha20 0xCCA8, legacy
  DHE AES-CBC 0x0067 fallback; TLS12 fallback retry with RFC 7507
  SCSV). Transcript 32768 with overflow FLAGGED (BUG-0078); alert
  capture + truncation detection (BUG-0228).
- **SSH client/server**: KEX curve25519-sha256 (RFC 8731)
  preferred / diffie-hellman-group14-sha256 fallback; host keys
  rsa-sha2-256/512 + ssh-rsa; aes128-ctr preferred / aes128-cbc
  fallback; hmac-sha2-256. The host test server
  (`tools/paramiko_sshd.py`) logs the negotiated DH shared secret
  K for cross-checking against the kernel `dhtest`.
- **OTA**: the package SHA256 verifier.

## 5. The test faces

- `cryptotest` (crypto op 1): header banner
  `"Crypto self-test (NIST vectors):\n"` then per-primitive
  `    SHA-256: PASS`-style lines (SHA-256, AES-128, HMAC-SHA256,
  HMAC-SHA384).
- `dhtest` (crypto op 2): DH modexp golden tests + ECDH/X25519
  end-to-end checks (ok_e/ok_K PASS/FAIL lines) +
  `"DH modexp scale sweep (truth vectors, python3 pow()):\n"`.
- Host harnesses (`make test`): AEAD/SHA (RFC 8439 + NIST),
  bignum/P-256, X25519 (RFC 7748), RSA + X.509 (openssl fixtures,
  SKIP-FIXTURE declared), TLS 1.3 key schedule (RFC 8448 +
  KeyUpdate KATs), the P0 TLS batches (BUG-0022..0027, includes
  the kernel `net_tls.c` directly), the A401 negative-length DER
  probes at all four TLS entry points.

## 6. Audit-trail notes

The famous crypto-adjacent fixes both regression-tested now: the
TCP RX checksum chain bug (double complement) and the TLS
mid-handshake hostname bug. The DRBG replacement (xorshift32 ->
HMAC_DRBG) is the load-bearing one: every key the kernel
generates (SSH session keys, TLS premaster secrets) flows from
`crypto_random*`.

## 7. The L1 surface (2 ops, both captured)

```c
#define L1SVC_CRYPTO_CRYPTOTEST 1   /* cryptotest              */
#define L1SVC_CRYPTO_DHTEST     2   /* dhtest                  */
```

- **Trigger**: a developer or the regression gate runs
  `cryptotest` / `dhtest` at the ush prompt (or via `sysdiag`'s
  selftest lab / the `run` mechanism).
- **Processing**: both route through `crypto_l1_dispatch` into
  `core_kcap_run_fn`-captured command bodies that iterate the
  vector tables and print PASS/FAIL per primitive.
- **Impact**: the PASS lines are regression anchors (check 11 of
  the 31-check gate); a FAIL here means the primitive tables or
  the DRBG changed behavior - stop shipping and diff first.

Family declaration:
`OC_SERVICE_DECL_L1("crypto", "crypto service (aead/sha/rsa/dh/x509 + ring-3 surface)", 0, 0, crypto_l1_dispatch);`

## 8. Where each primitive is consumed

| Primitive | Consumers |
|---|---|
| HMAC_DRBG (`crypto_random*`) | SSH session keys, TLS premaster/traffic secrets, any nonce |
| AES-GCM / ChaCha20-Poly1305 | TLS 1.3 record protection; TLS 1.2 GCM suites |
| AES-CBC | the legacy TLS 1.2 DHE-RSA-AES128-SHA256 (0x0067) fallback the HTTPS E2E pins |
| SHA-256/384/512 + HMAC | handshake transcripts, certificate digests, HKDF, the DRBG itself |
| HKDF / TLS 1.3 key schedule | RFC 8446 section 7.1 (`net_tls13_ks_expand_label`, `derive_secret`) |
| DH modexp (group 1 / group 14) | SSH KEX fallback (diffie-hellman-group14-sha256), the legacy TLS DHE suite |
| X25519 / P-256 | TLS 1.3 + SSH curve25519-sha256 KEX; ECDH self-tests |
| RSA | TLS/SSH server-cert verification, ssh-rsa/rsa-sha2 host keys |
| X.509 + root store | the TLS client's chain validation + SAN dNSName hostname check |
