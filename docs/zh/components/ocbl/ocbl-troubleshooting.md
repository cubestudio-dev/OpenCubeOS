# OCBL：故障排查与状态码

OCBL 与恢复链报告什么，以及每份报告的含义。

## 保留区记录（OCBL 写入的内容）

| 字段 | 含义 |
|---|---|
| `magic` / `ver` / `size` | `"OCB1"`、版本 1、28 字节布局 |
| `kind` | 记录种类（见下） |
| `stall` | 启动挂死所在的阶段 |
| `seq` | 判定时状态区的启动尝试序号 |
| `ts_unix` | 判定时刻，unix 秒（CMOS） |
| `silence_sec` | 实测的无进度秒数 |
| `routed` | 1 = OCBL 已自动启动 OCIRE |
| `boot_fails` | 连续判定失败次数 |
| `checksum` | 前置载荷字（小端 u32 视角）的反码和——区分真实记录与复位垃圾的校验 |

### 记录种类

| 种类 | 含义 |
|---|---|
| NONE | 无记录（一次正常启动） |
| BOOT_FAILED | 看门狗捕获、经判定的启动失败 |
| USER_REQUEST | 用户在菜单中选择了 OCIRE 条目 |
| WAKE_FAILED | SLEEP_ARMED 在重启后仍然置位（唤醒向量崩溃或睡眠中死亡） |

## 接管菜单（路由之后，位于 OCIRE）

两个阻塞菜单共享一个按键循环。**其余按键一律忽略，且没有超时**
——机器留在恢复环境，直到人做出决定。

### 启动失败接管（连续两次判定失败）

```
[R] 回滚到上一个 OCOS 版本
[C] 继续并再次尝试启动 OCOS
```

### 唤醒失败接管（SLEEP_ARMED 在重启后仍置位）

```
[W] 从睡眠唤醒失败。（诊断信息）
[R] 回滚到上一个 OCOS 版本
[C] 尝试正常启动 OCOS
```

- `[R]` 翻转 OCOS 的 A/B 槽标志（`next_B` / `ok_B` /
  `bootfail_B` 协议——与 GRUB 配置及 OCBL 扫描器实现的语义
  相同）并重启。
- `[C]` 清除失败记录并重启进入 OCOS。
- `[W]` 打印唤醒失败诊断（判定时刻、静默时长、连续失败次数，
  以及 SLEEP_ARMED 仍然置位的含义说明）。

## 解读一次启动失败

OCIRE 把记录字段打印为修复建议：挂死阶段（0 BOOT / 1 KMAIN /
2 SCHED / 3 DRIVERS / 4 SERVICES / 5 L1_LAUNCHED / 6 L1_READY /
255 RUNTIME）、实测静默时长、启动失败计数与启动序号。低阶段
挂死且 `silence_sec` 大，指向硬件或内核早期问题；挂在 255
（RUNTIME）表示系统已起来、之后才挂死。

## /HANGAT 诊断钩子

当载荷卷上存在一个字节、内容为 `1`..`7` 的 `/HANGAT` 文件时，
OCBL 在内核命令行追加 `oc.hang=N`，内核在记录完阶段 N 后立即
故意停机——阶段看门狗已布防，因此真实的 看门狗 -> 复位 -> 诊断
链路与生产环境完全一致地触发。`7` 在 L1_READY 之后、运行时心跳
运行中停机（运行时挂死场景）。该钩子让**出货镜像**无需测试专用
内核即可做失败演练；文件不存在时它是完整的无操作。

## 监视器自禁用

若本次启动中固定监视页对 OCBL 不可用（BIOS：没有 E820 可用区域
覆盖它们；UEFI：AllocatePages 保留失败），整个监视器**本次启动
自禁用**——完全不写低内存——内核从命令行标志 `oc.stmon=off`
获知此事。

## 已声明的 UEFI 看门狗限制

挂接 i6300ESB PCI 看门狗设备时，UEFI（OVMF）下 OCBL 载荷路径在
槽位扫描后停止；对未修改的 WP07 前加载器的对照重构建以字节一致
的方式复现，说明该缺陷早于 WP-07。不挂该设备时整条 UEFI 监控
路径已实测验证。**BIOS 形态承载完整且经过验证的看门狗机制**，
其链路必须全通（实际全通）。见
[KNOWN_ISSUES](../../root/KNOWN_ISSUES.md) K-02。

## 与 OCIRE 恢复流程的一致性

菜单所守卫的恢复链是 WP-07 闭环：严格**手动**的 `update` 命令
（无网络、无定时器）从真实 GPT ESP 读取
`\EFI\OpenCube\ocire-update.bin` 及其 `.sig`，用内置 **Ed25519**
公钥验签，刷写双分区恢复盘的**非活动**槽，对回读做散列，再经
LBA 1024 的 A/B 标志扇区布防。坏镜像绝不会替换正在运行的槽——
接管菜单针对的是**运行系统**失败的情形，而不是更新路径。

另见：[双固件引导与 A/B 槽判定](ocbl-ab.md)——标志扇区与状态区
语义。
