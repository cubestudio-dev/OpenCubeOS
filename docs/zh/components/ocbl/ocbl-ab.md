# OCBL：双固件引导与 A/B 槽判定

OCBL 如何决定启动什么、恢复盘上的 A/B 槽如何判定、两个低内存状态
区各是什么含义。该契约由三个独立构建逐字节共享——OCBL（`ocbl/`）、
OCOS 内核（`src/L0/`）、OCIRE 恢复内核（`ocire/`）——定义在
`include/ocbl_state.h`。

## A/B 恢复盘：两个独立物理分区

WP-07 恢复盘以**两个独立物理分区**承载 OCIRE：

| 槽 | 分区 | 起始 LBA | 容量 | 文件系统 |
|---|---|---|---|---|
| OCIRE-A | p1 | 2048 | 64 MiB | 真 FAT32，支持 LFN 读取 |
| OCIRE-B | p2 | 133120 | 64 MiB | 真 FAT32，支持 LFN 读取 |

这是真正的双分区布局——**不是**一个分区里放两个镜像文件。较老的
FAT12 0xEE 影子卷介质仍可挂载（兼容性）；现行介质上影子布局已
退役。

槽位选择块是 **LBA 1024 处的 A/B 标志扇区**，位于 OCBL 镜像与首个
分区之间——一个 24 字节的 `OCIREAB1` 结构，OCBL 与 OCIRE 逐字节
共享其布局：

| 字段 | 含义 |
|---|---|
| `magic[8]` | `"OCIREAB1"` |
| `active_slot` | 1 = A，2 = B（最后一次确认良好的槽） |
| `try_slot` | 0 = 无；否则正在尝试的候选槽 |
| `attempts` | 对 `try_slot` 已作出的启动尝试次数 |
| `flags` | 位 0 = 脏 |
| `boot_count` | OCIRE 成功启动次数 |

## 槽位判定流程

1. OCBL 读标志扇区并选槽：有 `try_slot` 则用之，否则用
   `active_slot`。
2. 加载候选**之前**先递增其 `attempts`。
3. 候选无法加载时，OCBL 回退到另一个槽。
4. 正常运行的槽由 **OCIRE 确认**（晋升）：恢复内核在一次良好启动
   后更新标志扇区，`active_slot` 由此为真。

OCOS 的 A/B 回滚使用与被它取代的 GRUB 配置相同形态的协议（磁盘
首个系统卷上的 `next_B` / `ok_B` / `bootfail_B`）——接管菜单的
Rollback 键翻转的正是这些标志。

## 两个状态区

两块固定低内存实现启动状态监视。两处都经参考平台实测在热复位中
存活（复位的擦除停在 EBDA，0x9FC00）；**冷启动或断电会清除它们**，
因此每个消费者在校验魔数与反码校验和之前不信任任何记录——没有
记录只意味着一次正常启动，绝不误判为失败。

| 区域 | 地址 | 大小 | 写入者 | 读取者 | 含义 |
|---|---|---|---|---|---|
| STATE | `0x98000` | 4 KiB | 内核**盲写**（从不回读）；OCBL 在移交时重新初始化 | OCBL、OCIRE | 内核此刻在做什么：阶段、心跳、进度时钟 |
| RESERVED | `0x9B000` | 4 KiB | OCBL（判定或用户请求） | OCIRE，重启后 | 事后启动记录 |

两页在每个用户地址空间中都是仅监督者可见——L1 应用够不到——且
都在 multiboot2 内存映射中被划为 E820 保留，任何载荷都不会分配
它们。

### 启动阶段（STATE 区的 `stage` 字段）

数值顺序即启动顺序；内核只前进：

| # | 阶段 | 含义 |
|---|---|---|
| 0 | BOOT | kmain 之前的移交 |
| 1 | KMAIN_ENTERED | kmain() 已进入 |
| 2 | SCHED_READY | 调度器 + 核心机制 |
| 3 | DRIVERS_READY | 驱动初始化完成 |
| 4 | SERVICES_READY | 根服务就绪 |
| 5 | L1_LAUNCHED | 默认 L1 应用已启动 |
| 6 | L1_READY | ush 已服务（首次系统调用） |
| 255 | RUNTIME | 标记：运行中挂死 |

## 失败计数与清零条件

- **单次**被判定的启动失败只递增记录的 `boot_fails` 计数并
  **重试 OCOS**。
- 计数达到 **2**（`OCST_BOOT_FAILS_ROUTE`）时，OCBL 自动把机器
  路由进 OCIRE——接管。
- 内核在**确认良好启动后**（到达 L1_READY）清零计数器，所以
  "连续"是诚实的：一次坏启动后跟一次好启动，计数器归零。
- 计数器使用记录中原先的保留字节——记录布局未变，旧读取者继续
  工作。

## 看门狗接力（谁在给谁计时）

multiboot2 移交之后 OCBL 已不再执行，因此各阶段超时由
**i6300ESB 硬件看门狗**强制：OCBL 在移交前布防引导预算，内核在
每次阶段推进时重布阶段预算，并在运行时以 1 秒节拍喂狗。

| 阶段 | 预算 |
|---|---|
| 启动起点 -> KMAIN_ENTERED | 30 秒（OCBL 移交前布防） |
| 各中间阶段 | 10 秒 |
| L1_LAUNCHED -> L1_READY | 30 秒 |
| 运行时（L1_READY 之后） | 15 秒心跳（1 秒节拍喂狗） |

内核挂死即停喂狗，硬件复位机器，而复位后再次运行的 OCBL 读取
状态区、依据阶段与实测静默时长判定停滞（**8 秒**的阈值把手动
热复位——实测静默不足 ~4 秒——与真实看门狗捕获的挂死——至少
达到运行时预算——分开），把 BOOT_FAILED 写入保留区，在屏幕上
显示失败通告 4 秒，然后发 8042 复位脉冲。

## SLEEP_ARMED（唤醒失败检测器）

内核在写入 SLP_EN（进入 S3/S0ix）之前立即置位 `SLEEP_ARMED`
标志，并在恢复路径上清除它。重启后仍发现该标志置位，意味着唤醒
向量崩溃或机器在睡眠中死亡：OCBL 记录 WAKE_FAILED 并路由 OCIRE，
后者给出唤醒失败接管菜单。
