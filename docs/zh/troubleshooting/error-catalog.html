报错库 — 按子系统罗列的每条失败消息 ​

这是全仓失败消息清单：你实际看到的字符串， 按组件与文件组织，每条附触发 → 排查 → 修复。代码树中存在 约 1700 条不同的错误语义字符串；重复模板在此合并并附文件 清单，因此本页是完整地图而非样本。数值代码在 error-codes.md；不打印任何内容的失败在 silent-failures.md。

排查命令按 ush> 提示符拼写。万用的阶梯：health → dmesg 100 → 该家族的状态命令 → 该家族的 _test 桩 （../manual/hidden-commands.md）。

1. OCBL — 引导加载器（5 类） ​

1.1 BIOS 载荷路径（ocbl/common/ocbl_main.c） ​

  • [boot] FATAL: payload volume remount failed — 内核加载前的 /boot 重挂载失败。排查：引导 ISO 的另一个条目； 捕获串口（-serial file:）。修复：从可正常引导的环境重新执行 install <dev> 或 grub-install <dev>。
  • [boot] VBE FAILED (kernel will refuse) — 无 VBE 模式；OCOS 要求 framebuffer。修复：启用 VGA/VBE 设备（QEMU：默认 VGA； 真实硬件：BIOS 视频设置）。
  • [boot] FATAL: kernel load failed — /boot/opencube.elf 的 ELF 加载失败（缺失/损坏）。修复：重新安装，或 引导槽位 B / ISO 并修复该卷。
  • [boot] ACPI S5 shutdown / [boot] S5 did not power off; halting — 菜单关机路径；第二行表示主板忽略 S5。请使用 物理/宿主机电源控制。

1.2 UEFI 变体（ocbl/efi/efi_entry.c + 辅助文件） ​

  • [efi] FATAL: fixed low-memory windows not ... — 0x98000/0x9B000 的 OCST 岛被固件占用。修复：固件设置中释放 低内存的选项，或引导 BIOS 变体。
  • [boot] FATAL: chainload volume remount failed（含载荷变体） — 目标 ESP 不可读。修复：在另一台机器上校验该 ESP。
  • [boot] GOP FAILED (kernel will refuse) — UEFI GOP 未给出模式。 修复：固件视频设置；OVMF 默认值可用。
  • [boot] FATAL: kernel load failed — 同 §1.1。
  • [efi] FATAL: memory map failed / [efi] GetMemoryMap failed: 0x<hex> — EFI 内存服务拒绝。重试；固件 bug 类。
  • [efi] EBS retry (0x<hex>) / [boot] FATAL: ExitBootServices refused — ExitBootServices 重试后仍致命：某个引导驱动仍 持有过期的 map key。更新固件 / 使用 BIOS 变体。
  • Chainload 辅助：[boot] FATAL: chainload buffer alloc failed、 chainload target not readable: <path>、[boot] LoadImage failed: 0x<hex> — 外来加载器缺失/非 PE。对非 PE 桩测试盘属于 预期；修复目标 ESP。
  • [boot] GOP: SetMode failed, keeping current — 良性；使用 当前模式。

1.3 Chainload（ocbl/bios/ocbl_chain.c） ​

  • [chain] VBR read failed — 所选卷的引导记录 不可读。修复：该卷实际不可引导；选择另一个 条目。

1.4 引导失败判定器（ocbl/common/ocbl_statemon.c） ​

  • 屏幕：Open Cube OS failed to boot at stage: <STAGE> + Rebooting to recovery... — OCBL 判定 RTC 静默 ≥ 8 s 超出 阶段预算（启动 30 s / 每阶段 10 s）。下一次引导 自动单次路由到 OCIRE。
  • 串口：[state] previous boot judged FAILED at stage <STAGE_NAME> (silence <n>s) - BOOT_FAILED recorded。
  • 如实的非失败（信息性）：previous boot shut down cleanly (seq <n>)、warm reset with recent progress (silence <n>s) - not a failure、previous boot armed no payload - no failure。
  • [state] BOOT_FAILED record pending (stall <n>s) - detection degrades to the next reset — 无硬件 watchdog 强制预算；判定 改在下次复位时落地。
  • [state] USER_REQUEST recorded - recovery session — 你在菜单中 选择了 OCIRE。
  • [rtc] clock frozen - skipping the dwell — RTC 不走字；静默 无法测量。修复：RTC 电池 / 启动后运行 rtc。
  • (the kernel will halt after the stage) — /HANGAT 诊断已 武装；见 boot-failures.md。

1.5 扫描/菜单标签（ocbl/common/ocbl_scan.c） ​

不是错误，而是扫描的可见结果：Open Cube OS (slot B|A, <size> KiB)（当 next_B+bootfail_B 强制槽位 A 时附 rollback）、OpenCubeOS Setup (OCSE)、OCIRE recovery、 EFI loader、<volume> (cd|hd<N> gpt|p<N>)。串口轨迹： [scan] entries: <N>。缺少条目意味着未找到标记文件 — 见 boot-failures.md §scanner。

2. OCIRE — 恢复内核（5 类） ​

2.1 监督器（ocire_bootsvc.c） ​

  • Reset failed on this machine; halting. — 8042/CF9 复位均 无效。使用宿主机电源控制。
  • Supervisor: no OCIRE recovery volume found — hd1 0xEE+FAT12 卷缺失。修复：带恢复分区重新安装 （OCSE 安装器会创建）。
  • Supervisor: recovery volume malformed (mailbox/log missing). Entering the full shell. — 影子卷存在但其 邮箱损坏。运行 syscheck，然后从完整 shell 执行 repair quick。
  • Supervisor: mailbox write failed - skipping the reboot to avoid a reset loop; entering the full ... — 防复位循环防护 （BUG-47 修复）。邮箱不可靠；重启前先修复它。
  • WARNING: log agent digest mismatch + The agent will NOT be injected (tamper guard). — 代理镜像与 邮箱摘要不匹配。按篡改或损坏处理：syscheck、 repair。
  • Supervisor: /BOOT/OPENCUBE.ELF not found on the ... / OCOS kernel too large (<n> ...) — kexec 源缺失/超大。 修复：syscheck 然后 repair 从黄金集重建系统卷。
  • Supervisor: FATAL - cannot write the mailbox. — 嵌入通道 已死；恢复路由降级。repair。
  • Watchdog arm FAILED - continuing without it — 6300ESB 缺失； 恢复在没有硬件缰绳的情况下继续。
  • Supervisor: kexec refused the image (rc <n>) — OCOS ELF 未通过 校验。syscheck。

2.2 syscheck / repair（ocire_recover.c） ​

卷校验判定（检查 1-10）：FAIL、BAD (magic/state invalid)、BAD (magic/cursor invalid)、MISMATCH (agent image vs mailbox digest)、FAIL (cannot parse)、... MISSING/UNREADABLE、 ... DIGEST MISMATCH、I/O ERROR、4-10. skipped (volumes incomplete)、8-10. skipped (no manifest) — 各自指名一个损坏 部件；repair 是它们共同的应对。

  • logread: recovery volume not found (run syscheck). / logread: cannot read /LOG/BOOT.LOG. / logread: BAD ring header (magic/cursor) - use 'repair quick' to reset it. — 引导日志 通道；repair quick 重置环形缓冲。
  • 修复流程失败：REBUILD FAILED、RESET FAILED、 FAILED - aborting (volume left as-is).、failed (re-run or use another golden set)、cannot verify files. Aborting. — 重新运行 repair；若重复出现，则是黄金集本身损坏。
  • WARNING: this REFORMATS the OpenCubeOS system volume; all data on it will be lost. Type YES to continue: — 刻意的 破坏性确认；必须准确输入 YES。

2.3 停滞解释（ocire_ocbl.c） ​

The kernel failed to start or stalled in its earliest ...（3 种阶段 变体，均以 retry the boot. 结尾）、The default L1 application (ush) failed to come up. Run syscheck to verify the system image, then retry ...、Unknown stall point. Run syscheck ... — 这些是 OCBL 判定的用户面映射；遵循其中嵌入的建议。 引导记录回显行（Recovery session requested by the user (seq <n>)、No boot failure was judged - this is a manual recovery session.、Previous boot FAILED at stage <STAGE>）说明你为何 处于恢复环境。

2.4 异常（ocire_idt.c） ​

<vec #XX name> + error 0x<hex> + System halted. — OCIRE 自身内部的未处理故障（7 个向量名：#DE/#OF/#UD/#TS/#GP/#CP， 回退 unknown vector）。捕获串口；这是 bug 类。

2.5 Shell / 引导如实性（ocire_shell.c、ocire_main.c） ​

  • Unknown command: <cmd> — 恢复 shell 很小；help 列出 全部命令。
  • Power off not supported on this machine; halting. / Reset failed on this machine; halting. — 平台限制。
  • ACPI: not found - legacy power ports will be used — 如实 降级，不是错误。
  • === ocire-agent: klog snapshot refused === — 仅限 guard 的 klog op 拒绝了非 guard 调用方；探测该通道时属于预期。

3. OCSE — 安装器环境（6 类） ​

3.1 阶段失败（ocse/kernel/main.c、ocse_main.c） ​

  • [ocse] STAGE <n> FAILED: <what> — 安装器内核的某个引导 阶段失败（串口 + VGA + 引导日志）。阅读 <what>；镜像的 内核消息见下文 §5/§6。
  • [ocse] FATAL: no usable disk - halting — 无安装目标。
  • ... B, ocblmbr.bin MISSING / [ocse] medium check: ocos.tar MISSING — 安装介质不完整（刻录/下载损坏）。 重新下载 ISO；核对大小/SHA。
  • direct rendering (alloc failed) — 安装器 GUI 无法分配 其 framebuffer。

3.2 ocsecl — 命令行（ocse_cl.c） ​

导航/文件：ls: bad path、cd: bad path、cat: cannot open 、 write: cannot create 、touch: cannot create 、mkdir: cannot create (exists, or parent missing)、rmdir: cannot remove (not found, not a directory, or not empty)、rm: cannot remove 、cp: bad source name、cp: destination path too long、cp: copy failed (err <n>)、 mv: moving a directory across parents is not supported — 标准的 路径/参数错误；先 ls/pwd 目标。 分区：mkpart: bad start / bad end、rmpart: bad partition number、setflag: bad partition number、install: bad partition number — 数值防护。rmpart: WARNING: deleting a partition DESTROYS ITS DATA! 和 : WARNING: formatting DESTROYS ALL DATA on the target device! 是破坏性确认。 tar/dd/sha：tar: cannot open 、tar: out of memory、tar: archive error (<n>)、dd: cannot open input: <d>、dd: I/O error (<n>)、 sha256sum: read error、sha256sum: bad sector count — 介质或 内存问题。 杂项：' - unknown command (try 'help')、click: bad coordinate。

3.3 向导字典（ocse_i18n.c） ​

disk not found: 、partition not found、invalid range (need start < end <= disk size)、format failed、... failed (busy or not a mount point)、install: FATAL - install medium incomplete (OCOS.TAR / OCBLMBR.BIN)、config: invalid key or value、A command failed: — GUI 向导的失败文案（EN/zh 成对）；每条映射到与其同名的 ocsecl 步骤。

3.4 安装器（ocse_inst.c）— 步骤链 ​

ocbl-install: cannot open <f>、ocbl-install: stage1 verify FAILED、 ocbl-install: core verify FAILED、install: recovery partition skipped - 、recovery kernel unreadable、mkpart failed、 created partition not found、partition device missing、 mkfs.fat32 failed、mount failed、cannot create /boot/ocire.elf on it、recovery kernel short read、install: FATAL - no such partition: <p>、install: FATAL - extraction failed、 install: FATAL - /boot/opencube.elf missing after extraction、 install: FATAL - ocbl-install failed、install: FATAL - could not set the boot flag、config: cannot write the configuration — 该链 是顺序的；第一条消息指名损坏的步骤。几乎全部 归结为：目标磁盘损坏（先运行磁盘检查）或介质损坏 （§3.1 的 MISSING 类）。

3.5 输入防护（ocse_wizard.c） ​

[wizard] refuse: existing ...、mount (too long)、install (too long)、write /mnt/etc/users (record too long)、The user record (name + full name) is too long for the ... — 长度防护；缩短 输入。

3.6 mkfs + 镜像池（ocse_mkfs.c） ​

: device name too long — mkfs 参数防护。OCSE 的其余 驱动/文件系统/内核错误文件逐字节镜像了 §5/§6 的 OCOS 字符串 （相同的 gzip/tar/config 枚举，相同的 fs/驱动消息） — 一个共享池；按字符串去重，不按文件。

4. OCOS 内核（7 类） ​

4.1 引导 FATAL 与阶段 FAIL（core_boot_main.c） ​

硬失败（停机）：

  • [oc] FATAL: bad multiboot2 magic — 未经 OCBL/GRUB mb2 引导。 修复：通过 ISO 的 OCBL 菜单引导。
  • [oc] FATAL: multiboot2 parse failed — mbi 标签遍历遇到非法 标签。捕获串口；加载器 bug 类。
  • [oc] FATAL: fb_init failed — 未传入 GOP/VBE 模式。修复 引导加载器的视频交接。

阶段 FAIL 判定（[HH:MM:SS.mmm] <stage>: FAIL）：

  • WP-01 extension self-test — 4 个 L1 扩展金丝雀之一 失败。内核面回归；报告。
  • exception self-test — #UD/#PF/#BP 自测计数器错误。报告。
  • ACPI: RSDP not found (no ACPI power paths) — 无 RSDP；电源 功能降级为遗留端口。
  • CMOS RTC: probe inconclusive (VRT not set) — RTC 电池缺失 （VM 恒如此）；date 回退为毫秒自启动。
  • HPET: no usable ACPI HPET table / ACPI PM timer: no usable PM_TMR_BLK — 定时器源降级；TSC/PIT 继续。
  • kmalloc/kfree self-test — 堆往返失败。报告。

4.2 L1 启动（core_boot_l1launch.c） ​

  • l1 launcher: no default L1 app declared; entering recovery shell — 构建损坏（注册表为空）。报告。
  • l1 launcher: failed to start the default L1 app; entering recovery shell — ush 启动失败。引导 ISO，运行 help_a_test。
  • l1 launcher: default L1 app exited; L0 halting (reboot or use the boot menu) — ush 返回（会话结束；shutdown 后属正常）。

4.3 OCST 状态区（core_boot_state.c） ​

  • absent - stage recording only, no hardware reset — 无 6300ESB watchdog：引导失败检测降级为下次复位判定。
  • [ocst] /HANGAT diagnostic: will halt after stage / [ocst] HANGAT: deliberate halt with interrupts off / [ocst] HANGAT runtime: deliberate halt with — /HANGAT 文件存在！从载荷卷删除 /HANGAT（见 boot-failures.md）。
  • [ocst] L1 ISOLATION FAILURE: a user page covers 0x<hex> — 某个 用户 PTE 映射了仅限管理者的 OCST 邮箱窗口。安全检查 触发；立即报告。

4.4 ELF 加载器，静态路径（core_usermode.c） ​

  • [user] no address space — 进程创建时 PMM/VMM 耗尽。 mem、free；停止吃内存的作业。
  • [user] not an ELF file / [user] not ELF64 — exec 目标 不是有效 ELF64。对 badapp 类固定件属预期。
  • user: process table full (max <N> processes) — 并发进程 过多。ps，kill <pid> 清理掉队者。

4.5 动态 exec（core_usermode.c，dynlink: 前缀） ​

PT_INTERP: (offset out of bounds)、dynlink: PT_INTERP not present、 dynlink: no embedded ld.so for path、dynlink: ld.so too small / not an ELF file / not ELF64 / has no PT_LOAD segment、 dynlink: main image failed ELF header checks、dynlink: main PT_LOAD out of user window、dynlink: failed to map main PT_LOAD、 libfoo 孪生 — 动态链断裂；几乎总是构建或 注册表完整性问题。用 ldd <program> 验证；重新运行 l1test。

4.6 程序头校验（两条路径） ​

[user] bad phentsize、[user] program-header table out of bounds、 [user] PT_LOAD file range out of bounds、[user] PT_LOAD vaddr+memsz overflow、[user] PT_LOAD memsz < filesz、[user] PT_LOAD vaddr in kernel space、[user] PT_LOAD segments overlap — 被加载的 ELF 畸形/敌意。如果是随系统发布的程序， 报告；如果是你自己的，修复链接脚本。

4.7 调度器 + 配置（core_sched.c、core_lib_config.c） ​

  • PANIC: idle task stack allocation failed - halting — 调度器初始化 OOM。增加内存（512 MiB 从容）。
  • klog WARN kthread %s: guard page unmap FAILED at 0x%lx (stack protection absent) — 2 MiB 大页拆分失败；该任务 在无栈溢出防护下运行（bug-list BUG-4）。无害但 值得报告。
  • config: backend bring-up FAILED — /etc 无法挂载； 配置降级为 ramfs（重启后变更丢失）。见 storage-issues.md。
  • config: invalid auto_check value - using no (safe default) / config: invalid online_update value - using yes (default) — 配置文件含垃圾值；已应用默认值。用 config set 修复。

5. OCOS 服务（21 类，按家族） ​

5.1 audio ​

  • play: out of memory / play: device error — 分配或设备 失败。sound 列出设备；mem 检查内存。
  • : unknown device '<name> — play -d/volume 目标未 注册。使用 sound 中的名字。
  • [audio_rw_test] kmalloc(48000) failed => FAIL — 环回测试 期间 OOM。
  • [audio_rw_test] no sound cards registered => SKIPPED — 如实 跳过；接入音频设备（QEMU -device intel-hda）。
  • driver rejected the rate / (unsupported, correctly rejected) => PASS — 负面固定件：非法速率就应当被拒绝。
  • QEMU-10 的 hda 模型在 44.1 kHz 上死循环 — 已知模型限制； 真实硬件编程正常。

5.2 block — 缓存 + 设备保护 ​

  • blkcache: alloc FAILED - cache disabled (raw I/O) — 64 槽 LRU 写回缓存无法分配；系统继续 无缓存运行（更慢）。mem；若持续则报告。
  • blk: refusing device '<name> — 注册几何非法的设备。 驱动层问题；报告。
  • blk: write to protected device <name> REFUSED (ocire recovery disk) / blk: cached write to protected device REFUSED (ocire recovery disk) — 整盘 OCIRE 保护已武装；对恢复卷的写入 按设计被阻断。要修改该卷请使用 OCIRE 自己的 repair。

5.3 block — parted/mkfs/fsck 命令 ​

  • parted: device not found / : device name too long — 设备 字符串错误。先 lsblk。
  • mkfs.fat32: device not found / mkfs.fat32: device too small / exfat 变体（device too small (need at least 65 sectors, got <N>)、device too small for FAT + heap）/ mkfs.ext4: device not found — 目标检查。从 lsblk 挑一个真实且足够大的设备。
  • WARNING: formatting DESTROYS ALL DATA on the target device! — 确认提示；裸 y 继续。
  • fsck（仅 FAT32）：fsck: cannot read boot sector、fsck: invalid boot signature (not 0x55AA)、fsck: not a FAT32 volume (fsck supports FAT32 only; got invalid BPB)、fsck: unsupported bytes_per_sector (fsck reads raw 512-byte sectors; got <N>)、 fsck: out of memory、fsck: FAIL (<detail>)、fsck: FAIL (cluster count mismatch: counted <A> ... — 该卷不是可读的 FAT32。fatstat <dev> 显示解析的 BPB；若数据可弃则重新 格式化。

5.4 block — install/abdisk/grub-install 链 ​

  • grub-install: MBR gap too small for <N> — MBR 后间隙放不下 core.img。用 ≥ 1 MiB 间隙重新分区（现代布局）或使用 GPT。
  • grub-install: failed to write boot sector / failed to write core.img — 写入失败；检查介质。
  • abdisk 链：abdisk: device not found、device too small (need <N>)、WARNING - all data on <dev>、failed to write partition table、failed to register partition、mkfs.fat32 failed on p<N>、 mount p1 failed、failed to write grub.cfg、mount p2 failed、 failed to write slot A kernel、grub-install failed — 顺序的； 第一处失败才是真凶。磁盘损坏或目标过小 覆盖多数情形。
  • install 链：install: device not found、device too small (need >= 64 MiB ...)、disk too large for MBR (>2TiB) or too small、 failed to write partition table、failed to register p1、 mkfs.fat32 failed、mount p1 failed、failed to write /boot/opencube.elf、failed to write grub.cfg、grub-install failed — 同一解读规则。
  • (build system error) — 构建中缺失某个内嵌资产。 重新构建。

5.5 camera（UVC/IR/parallel/gameport/SCSI） ​

  • nec corrupted rejected、mjpeg truncated rejected、set format unknown rejected、set frame mismatch rejected、capture refused before start — 负面固定件；它们 PASS 才是正确行为。
  • no parallel port present - skipping live steps、no stick (timeout)、<N> failures - PASS|FAIL — 如实的硬件缺失 报告。

5.6 crash ​

  • crashlog: flush FAILED (no filesystem mounted?) — 无 VFS 挂载可写 /var/log。挂载一个卷，重新运行 crashlog。

5.7 crypto ​

  • 自测判定 SHA-256: FAIL、AES-128: FAIL、 HMAC-SHA256: FAIL、HMAC-SHA384: FAIL — 加密原语损坏： 构建/工具链问题；报告。

5.15 net — 核心 ​

  • 枚举：usb: GET_DESCRIPTOR(8) failed、SET_ADDRESS failed、 GET_DESCRIPTOR(18/config9/config) failed、SET_CONFIGURATION failed、hub GET_DESCRIPTOR failed — 设备未枚举； 重新插拔，检查 hub。

  • EHCI：ehci: port reset fail ccs=0 w=0x<hex>。
  • OHCI：ohci: reset timeout。
  • MSC：msc: CBW bulk out failed、msc: data phase failed、msc: CSW bulk in failed rc=<n>、msc: CSW bad signature or tag、 usb-msc: device not ready、usb-msc: inquiry failed、usb-msc: read capacity failed、 NOT registered (blk layer rejected block size <n>)。
  • 音频类：usbaudio: SET_INTERFACE failed、device rejected SET_CUR(SAM_FREQ)、SET_CUR(MUTE) rejected、SET_CUR(VOLUME) rejected。
  • 串口：usb-serial: configure failed。

7. l1apps（5 类） ​

7.1 共享 i18n 模板（250 个应用） ​

  • <app>: service call failed (rc=-1)（i18n 键 svc_call_failed） — L1SVC 桥返回 -1。统一排查：(1) 重新运行 — 瞬态？(2) health + dmesg 100（服务的 klog 行讲述 真相）；(3) 运行该家族的 _test 桩；(4) 若服务 本身报告健康，则是 op 参数问题 — 在 ../manual/function-dictionary.md 中查该命令的语法。
  • service call failed（向导变体，wiz_svc_failed） — mega 向导的副本；同一排查。
  • [save failed] / [save failed - stay in editor] — 编辑器保存 失败；通常是只读文件系统。

7.2 经典逐应用错误 ​

  • cat: cannot open （同模板：head/tail/sort/uniq/wc/awk） — 对路径执行 ls。
  • cp: cannot open '<src|dst>' / mv: ... — 同上。
  • rm: cannot remove '<path>' / rmdir: cannot remove '<path>' — 文件忙或非空。
  • mkdir: cannot create '<path>' — 已存在或无父目录。
  • ln: cannot create symlink (target must be an absolute path) / ln: hard link failed (rc=<n>) — 符号链接规则是仅限绝对路径。
  • chmod: cannot change mode / chown: cannot change owner / stat: cannot stat '<path>'。
  • write: cannot open / write: write failed on 。
  • awk: missing {print ...} — 微型 awk 只支持 {print ...}。
  • sed: unknown script — 只有 s///、-n Np、Nd。
  • date: ms since boot (no RTC driver) — 回退提示（VM）。
  • free: SYS_MEMINFO unavailable (kernel too old) / ps: SYS_PS unavailable (kernel too old) — 版本偏差。
  • run: fork failed / run: unknown program: <name>。
  • help: unknown option '<o>' / (registry listing failed)。
  • ush：ush: 'exit' is not available; use 'shutdown' to power off, 'reboot' to restart、ush: syntax error near '>' / near '<'、 ush: alias expansion too long、ush: fork failed、ush: command not found: <cmd>。

7.3 Mega 应用分发错误 ​

  • disk-tool: unknown op: <op>（及 files/net-tool/sound-tool/ sysdiag/hwinfo/power 变体）、files: unknown program: <p> — 逐字表未命中；help -w 列出现存内容。
  • update 向导状态（i18n 键 net_probe_failed、ab_probe_failed、 ab_missing、ab_mismatch、ab_warn、dns_fail、check_unknown、 install_skipped、install_failed、reboot_skipped） — 各自映射 一个向导步骤结局；打印的文本指名失败步骤。
  • WARNING: this destroys all data on that device.（disk-tool dt_warn） — 重输设备名防护路径。

7.4 ld_so（ring-3 动态加载器） ​

  • ': invalid ELF (magic/ELF64/ET_DYN/phdr bounds)、ld.so: bad main base 0x<hex>、ld.so: bad libfoo.so base 0x<hex> — 加载失败。
  • ld.so: symbol reloc with bad index in '<so>'、ld.so: COPY reloc with bad index in '<so>'、ld.so: unknown reloc type <n>。
  • ld.so: mprotect W^X failed for '<seg>' — W^X 强制失败。
  • ld.so: bad DT_NEEDED name in '<so>'、ld.so: cannot load '<lib>'、 ld.so: libfoo.so missing DT_SYMTAB or DT_STRTAB、ld.so: failed to relocate libfoo.so / main program — 动态链损坏；重新运行 l1test、so_test、dlsym_test。

7.5 测试应用 ​

  • p2test：UTF8-FAIL short write、READ0-FAIL、PIPE-FAIL round=<n>（+ pipe()=-1 (slot table exhausted?)） — live-fix 探针； FAIL 即其所守护修复的真实回归。
  • help 门（help_a_test 等）：FAIL = 注册表列表形态 变化 — 构建或 i18n 损坏。
  • g6_oom / stackovf / pf_test / sigsegv_test / int3_user / badapp — 刻意崩溃者；它们的"失败"输出是内核的 遏制通告（§kernel）。

8. 已知 bug — bug-list.md，1 个 P0 + 35 个 P1（3.0.0 导出） ​

P0 ​

  • BUG-AUD-2a-001（内核/系统调用安全） — ring 3 可通过 标准 read/write 系统调用触及 内核内存（细节因安全策略从略）。修复前： 将每个 ring-3 程序视为潜在特权；不要运行不可信二进制。

P1（症状 → 原因 → 应对） ​

  1. BUG-3 OCIRE — 一次 core_sched_task_states 调用后 中断被永久关闭（flags 恢复习语）。症状： 恢复内核在一次调度器调用后死寂。树中已修复； 旧构建复现则报告。
  2. BUG-4 内核栈守卫页解除映射在 2 MiB 大页上是空操作 （+ 过期全局 TLB）。症状：klog WARN kthread %s: guard page unmap FAILED 且栈溢出防护 变弱。已知；在跟踪。
  3. BUG-5 ush kill 竞态 — 受害者地址空间在 EXITED 标记前被 销毁；定时器节拍可能把受害者调度到已释放的 CR3 上。症状：kill 之后偶发 崩溃。已修复；wp01_killrace_test.py 守护它。
  4. BUG-6 exec 失败/OOM 路径泄漏整个地址空间 （user_process_create）。症状：失败的 exec 使内存缓慢消失。mem；重启清除。
  5. BUG-7 sys_execve 在新地址空间建成前销毁旧 地址空间；exec 无法优雅失败。症状：exec 失败硬杀 进程。已知。
  6. BUG-20 ACPI AML OpRegion 访问无边界检查 — 恶意 DSDT 可获任意物理读写。不要引导不可信 固件表。
  7. BUG-21 TLS 证书链校验失败仅警告并 继续。现在默认拒绝（HTTPS E2E 第 0 项）； 显式选择加入是 config set tls.insecure 1。
  8. BUG-22 DNS 事务 ID 硬编码 0x1234，应答 未校验 — 离线投毒可能。症状：敌意 LAN 上 离奇的解析结果。已知。
  9. BUG-24 IRQ 关闭定时器上下文中的 TCP RTO 重传可能在 ARP 中忙等；过期 ARP 项令机器死锁。 症状：丢包下的硬冻结。前后对比 tcpstats。
  10. BUG-31 ush 命令未找到路径无界拼接进 path[64]（栈粉碎）。已修复；仅在 当前构建上输入垃圾命令。
  11. BUG-32 Tab 补全向 line[512] 无界追加。 已修复（有界追加）。
