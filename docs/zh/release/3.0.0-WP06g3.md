# 3.0.0-WP06g3 — 真机修复批次（ocse_enc_fix）

事后剖析批次：WP06g2 现场测试的七起真机灾难，逐字节根因
定位并修复。外加每条路径上的恢复环境，以及 g3 的原始
目标（OCSE/OCIRE 编码修复）。

## 变更内容

- **磁盘探测匹配真实 PC（4.1）。** AHCI 探测不再匹配单一
  精确的 PCI 类码：RAID/RST 模式 SATA 控制器（类 0x0104，
  许多品牌机的出厂默认）现在可见，与经典的 0x010601 并列。
  NVMe 在真机容忍路径上获得超时重试和 disable-CC 重写。
  而且探测不再是黑盒：每个 AHCI 和 NVMe 控制器事件都记录到
  **串口行**（q35+AHCI 测试组在串口上显示 8 行 `ahci:`，
  旧内核显示零行）。
- **`serial_encoding utf8|gbk`（4.2）。** 内核串口输出默认
  UTF-8，按需转换为 GBK——中文串口工具（按约定是 GBK）
  现在能干净地渲染 `lang zh`。OCSE 的 `ocse_out` 采用同一
  标准（一套策略，不是两套）。
- **VMware 启动崩溃（4.3）。** OCBL 实模式栈现在顶在
  0x8E00（低于每个观测到的 EBDA），启动状态监视器读取
  BDA 0x40E 的 EBDA 基址，并在大 EBDA 会与状态区重叠时
  禁用自己的状态区。等待用户的真机
  确认。
- **OCIRE 在每条路径上（4.4）。** 主 ISO 携带
  `/boot/ocire.elf`；OCBL 菜单扫描并列出 "OCIRE recovery"；
  安装器写入**专属恢复分区**（从磁盘未分配的尾部新切割，
  FAT32，恢复内核流式写入其上——流式副本在本批落地，起因
  是 zh 字体增长暴露了固定缓冲读取）。安装后的
  磁盘带两个条目启动。
- **编辑器真正本地化（4.5）。** 共享编辑器核心中 21 条硬编码
  的英文 UI 字符串改经 `tr_()` 路由；nano 的图例、提示与
  快捷键在 `lang zh` 下是中文。
- **真正的 IME 预编辑缓冲（4.6）。** 拼音绝不进入文本：它
  在状态栏上渲染的预编辑条中组词（连同候选与 IME
  状态），失败的 IME 服务调用会报告，而不是把字母静默漏进
  文件。
- **差分渲染（4.7）。** nano 栏经 ANSI 定位钉在最后一行，
  只重绘变化的部分：测得的按键流每个字母携带**零**个换行
  （事后剖析测得每键 3 行滚动、每会话 8 次全栏
  打印）。
- **OCSE/OCIRE 编码修复（4.8，g3 的原始目标）。** 破坏整串
  转换的破折号映射（GB2312 0xA1AA 与 U+2014）在 OCSE 表和
  主内核字体 blob 两边都修复了；OCIRE 获得了汉字字体、
  UTF-8 解码和 zh 字符串（它的"乱码"是能力缺失）。支持
  zh 的 ocire.elf 大了 6 倍——见上面的流式安装器修复。
- **工具（4.9）。** 发布启动门禁重新匹配真实的串口
  横幅；"branches: ain]" 这个 CI 工作流残留查明是终端誊录
  幻影（字面 `[m` 被当作 ANSI 复位序列吃掉）——已做字节级
  审计，从 KNOWN_ISSUES 退役。
- **内核窗口瘦身。** 九个约 16-18 KiB 的静态 TLS 记录
  缓冲移到堆上（恒等窗口已收窄到 24
  KiB；CI 的 gcc-13 越过了它）。瘦身内核上 HTTPS e2e 7/7。
