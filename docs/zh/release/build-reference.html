构建系统全量参考（维护者手册） ​

Open Cube OS 构建的完整机制级参考：每一个伪目标、每一个内部 文件目标、每一个变量、每一个 -D 宏、每一个按文件的优化覆盖， 以及并行度 / 编译缓存机制。配套页面：guard-scripts （检查脚本）、ci-gates（CI 与发布链）、 tool-inventory（tools/ 全部 117 个文件）、 disaster-recovery（沙盒与推送通道）。

本文覆盖的构建文件：Makefile（顶层）、ocire/ocire.mk、 ocbl/ocbl.mk、ocse/ocse.mk、ocos/kernel/arch/{arm64,riscv}/build.mk， 以及入口封装 tools/build.sh 和 build.ps1。

1. 架构分派与入口 ​

ARCH ?= x86_64。任何超出 x86_64 arm64 riscv 的取值都会立即以 $(error unsupported ARCH '<ARCH>' - supported: x86_64 arm64 riscv) 失败——make 在运行任何一条命令之前即中止。

  • ARCH=x86_64（默认）：Makefile 的完整主体——内核、ISO、 src zip、OTA、QEMU、配置、缓存、测试——外加三个组件包含 （ocire.mk、ocbl.mk、ocse.mk）。
  • ARCH=arm64 / ARCH=riscv：整个 x86_64 主体被跳过，改为包含 ocos/kernel/arch/$(ARCH)/build.mk（仅 bring-up 壳；见 §7）。

三个等价入口构建同一产物：

入口相对裸 make 的附加能力
make <target>无——事实来源
tools/build.sh <target>依赖检测（每条命令对应的精确 Debian 包）、--install apt 回退、免 root 的 install-toolchain.sh 提示、OC_TOOLS 自动发现（/usr、/home/z/tools/grub、$HOME/tools/grub）、JOBS 并行度（默认 nproc）
build.ps1（Windows）经 WSL2（wsl.exe + wslpath）或 MSYS2/Git-Bash（cygpath）翻译成对 tools/build.sh 的调用；-Target（默认 all）、-Install

tools/build.sh 还暴露可脚本化 API（WP-13 规范 8）： build_all、build_iso、build_src、build_ota、config_load、 config_save、config_get、cache_lookup、cross_compile、 cross_toolchain_setup——source 该脚本即可调用。

.DEFAULT_GOAL := kernel：裸 make 只构建 build/opencube.elf。完整的 WP-13 流水线是 make all。

3. 内部文件目标 ​

3.1 order-only 前置与生成头文件 ​

目标规则要点存在原因
$(BUILD)mkdir -p build每个目标文件的 order-only 前置条件
$(GEN_DIR)/version_gen.hFORCE + 写入 .tmp、cmp -s 守护、仅变更时 mv产出 #define OC_VERSION_STAMP "<ver> build <build>"。-D 参数对 -MMD 不可见，因此增量构建曾保留过期横幅（WP-10-tui-qa：一个 ISO 在 -ga29ac53 的代码上启动了 -ga4d5342 横幅）。该头文件让版本变更对依赖图可见
$(GEN_DIR)/config_gen.h同样的 cmp 守护模式产出 OC_CONFIG_NVME/AHCI/VIRTIO_BLK 0/1，以及关闭时 driver_block_<x>_init() 的空操作桩；是 $(KERNEL_OBJ) $(STUB_OBJ) $(GRUB_DATA_OBJ) 的 order-only 前置条件——必须在任何目标文件编译前存在，但只有 .d 文件触发重建

3.2 两阶段内核链接 ​

KERNEL_OBJ + grub_boot_stub.o --ld--> build/opencube_base.elf (+strip)
embed_grub.py "$(OC_TOOLS)" base.elf --> ocos/kernel/generated/grub_boot_data.c
grub_boot_data.c --compile--> grub_boot_data.o
KERNEL_OBJ + grub_boot_data.o --ld--> build/opencube.elf (+strip)
  • $(STUB_OBJ)：core_boot_grubstub.c 单独编译（仅 stage-1 链接；从 KERNEL_C 中过滤掉）。
  • $(GRUB_DATA_C)：tools/embed_grub.py 把 GRUB i386-pc 的 boot.img（512 B）+ core.img（grub-mkimage，带盘上 cfg 所需模块）作为 C 数组内嵌——内核内安装器的载荷。内核 ELF 本身不被内嵌（GRUB 经 grub.cfg 把它作为 multiboot2 模块 挂载）。
  • $(KERNEL)：stage-2 链接还携带 $(L0_I18N_GEN) 和 $(IME_PHRASE_GEN) 作为前置条件，使 i18n/IME 表在链接时 是新鲜的。
  • -include $(KERNEL_OBJ:.o=.d)：BUG-025 FIX——-MMD -MP 头文件跟踪。OCIRE 和 OCSE 出于同一原因各带自己的 -include 行。

5.2 ocbl.mk（OCBL 引导加载器——双风味） ​

一棵源码树，两种风味：带 -mcmodel=small 的 -DOCBL_FLAVOR_BIOS，和带 -mcmodel=large 的 -DOCBL_FLAVOR_UEFI（每个地址都是 PE 转换器可重定位的 64 位 movabs）。内建的断言（违规即构建失败）：两种 stage1 风味都 恰好 512 B；tramp16.bin ≤ 0x300 B；handoff_blob.bin ≤ 0x1000 B；EFI PE 头检查（MZ / PE\0\0 / machine 0x8664 / subsystem 10）。include/ocbl_state.h 是每个 OCBL 目标文件的 前置条件（WP07a 过期地址现场抓出）。EFI 风味用 --emit-relocs 链接一个中间 ELF 并经 ocbl/elf_to_efi.py 转换（完整的 .reloc 目录；朴素的 ld -m i386pep 路线在 OVMF 下重定位 错误）。

伪目标：ocbl-bios（stage1 El Torito + MBR 风味 + core → ocbl_bios.bin、stage1_mbr.bin）、ocbl-efi （ocbl_x64.efi）、ocbl-iso（经 ocbl/build_test_iso.py 的 独立双固件测试 ISO——该脚本是硬前置条件，B1 现场抓出）、 ocbl-run-bios、ocbl-run-uefi、ocbl-scan-disks（经 ocbl/make_scan_disks.py 的 11 镜像机群；时间戳覆盖所有同级 镜像——B5-7 现场抓出）、ocbl-run-scan（启动机群：2 块 IDE 盘、3 块 virtio 盘、FAT + 裸镜像、1 张 CD + 测试 ISO）。

5.3 ocse.mk（OCSE 安装环境） ​

  • ocse-vendor-check——ocse/kernel/types.h 缺失即失败： "run tools/vendor_ocse.sh then tools/ocse_edits.py"。作为 每个 make ocse-elf 的前置条件运行。
  • ocse-elf → build/ocse/ocse.elf（单阶段链接、输出 -Map=、 filter-out driver_block_disk_setup.c——GRUB 时代的工具；该 过滤行逐字重复了 10 次，一个已知的外观瑕疵）。
  • ocse-iso → bash tools/build_ocse_iso.sh，它先对 ELF 运行 tools/check_bss.py（见 guard-scripts）。
  • ocse-clean；自己的 -include $(OCSE_OBJ:.o=.d)。
  • OCSE_CFLAGS 镜像内核参数集 + -DOCSE_RELEASE=\"<ver>-ocse\"
    • -DOCSE_BUILD。

5.4 arm64 / riscv build.mk（各 4 个目标） ​

make ARCH=arm64|riscv 替换整个 x86_64 主体。工具链 CROSS ?= aarch64-linux-gnu- / riscv64-linux-gnu-（Debian gcc-aarch64-linux-gnu / gcc-riscv64-linux-gnu，GCC ≥ 12）。 源码：src/L0/core/arch/<arch>/{boot.S,kernel_main.c}（裸机 入口 + UART + 心跳）。XCFLAGS：freestanding + -mgeneral-regs-only（arm64）/ -march=rv64imac_zicsr -mabi=lp64 -mcmodel=medany（riscv——无 FP：裸 -kernel 启动的 M-mode 没有 编程 mstatus.FS），两者都带 -Wall -Wextra -Werror -O2 -g -std=gnu11 -DOC_RELEASE_VERSION -DOC_KERNEL_BUILD。目标： all/kernel → build/opencube-<arch>.elf（+ readelf Class/Machine/Entry 回显）、run-bios → qemu-system-<arch> -machine virt [-cpu cortex-a57] -nographic -kernel、clean-arch。 链接：$(XCC) -T linker.ld -Wl,--build-id=none -Wl,--hash-style=sysv。

7. 按文件优化覆盖（9 × -Os，1 × -O0） ​

所有覆盖使用同一模式： $(OC_CC) $(filter-out -O2,$(CFLAGS)) -Os|-O0 -c $< -o $@。

文件级别原因（来自 Makefile 注释）
ocos/drivers/net/drv_net_wireless.c-Os无线/sd 驱动集——内核镜像必须留在 0x400000 恒等窗口内；链接器 ASSERT 按字节精确，-O2 实测超限 8 KiB
ocos/drivers/net/drv_net_iwlwifi.c-Os同一窗口纪律
ocos/drivers/net/drv_net_rtlwifi.c-Os同
ocos/drivers/net/drv_net_ath.c-Os同
ocos/drivers/net/drv_net_brcm.c-Os同
ocos/drivers/storage/drv_storage_sdhci.c-Os同
ocos/drivers/misc/drv_misc_mjpeg.c-Os代码生成敏感：-O2 错编一条可用路径（段错误被 4:4:4 宿主夹具抓到）；-Os 干净，且 JPEG 解码器不是性能关键
ocos/drivers/misc/drv_misc_camera.c-Os同一相机集原因
ocos/drivers/misc/drv_misc_camera_uvc.c-Os同
ocos/drivers/bus/drv_bus_acpi_aml.c-O0AML 解释器只在启动时运行一次；-O2 代码生成与重指针的值模型交互不良（kfree 中野指针导致启动崩溃），而 -O0 能干净解析现场 QEMU DSDT

历史备注（NAK 清理）：针对根级 tui/ 目录的两条 -Os 规则从未 匹配到真实目标文件，已被删除而非更新路径——现在激活它们会改变 一直以 -O2 交付的文件的代码生成。

8. 并行度与编译缓存 ​

  • 并行度：make -j$(nproc)（build.sh 的 JOBS，默认 nproc）。安全性来自每个目标文件的 @mkdir -p $(dir $@) 配方、order-only 前置条件（| $(BUILD)、| $(VERSION_GEN) $(CONFIG_GEN)）和永不搅动 mtime 的 cmp 守护生成器。
  • 编译缓存（OC_CC := bash tools/oc_cc.sh $(CC)）：缓存键 = 建立在（1）精确编译器身份（路径 + 版本串）、（2）完整参数表 （flags、-D 值、include 路径）、（3）源文件哈希、（4）源所 依赖的每个头文件的哈希（来自编译器自己的 -MM 输出——基于 内容，因此动了但内容没变的头文件仍然命中、mtime 没动但内容 变了的头文件仍然未命中）之上的 SHA-256。命中按字节一致还原 .o 和 .d；未命中则编译并把两者都存入。命中字节一致， 因此 reproducible-check 在缓存开启时依然有效。控制项： OC_CACHE_DIR（迁移）、OC_CACHE_OFF（绕过）；计数器落到 $(OC_CACHE_DIR)/STATS（由 cache-stats 读取）。
  • 增量完整性：所有 .d 文件的 -include（内核、OCIRE、 OCSE 各自包含自己的）、version_gen.h 重编译触发器，以及 userprogs_data.h 过期门禁，共同封住三类历史过期产物 （BUG-025、WP-10-tui-qa、WP06g1 catch-2）。
