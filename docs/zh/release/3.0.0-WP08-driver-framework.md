# 3.0.0-WP08-driver-framework — 驱动框架

L0 驱动框架批次：把"加驱动就是加文件"从命名约定升级为工程标准的六项能力
——元数据、设备树、电源钩子、热插拔事件、失败隔离与确定性初始化顺序。
旧 `OC_DRIVER_DECL` 路径原样保留、两路共存（存量驱动零修改，两个注册
路径都在启动时收集）。

## 变更内容

- **驱动元数据与依赖。** 新描述结构 `oc_driver_info_t`（名称、版本、
  作者、许可证、依赖列表、兼容设备类型、优先级提示、D-state 掩码，
  以及 init/probe/remove/suspend/resume 回调），经
  `OC_DRIVER_INFO_DECL` 注册进新的 `.oc_drvi` 链接段。旧宏签名与
  行为完全不变。
- **不依赖 ACPI 的设备树。** `core_devtree_*` 提供节点模型（ID、父
  节点、子节点、类型、MMIO/IOPORT/IRQ/DMA 资源、绑定状态、私有
  数据）、注册/注销、按 ID 或名称查找，以及按类型 / 按子节点 /
  深度优先遍历。框架本身不解析 ACPI、不枚举任何总线——WP-09a/
  WP-09b 将通过同一组注册调用填充设备树。
- **驱动级电源钩子。** `oc_pm_notify(D1..D3)` 按"子先于父"挂起，
  `oc_pm_notify(D0)` 逆序唤醒；未声明目标状态的驱动自动跳过。不含
  S-state 状态机、不含策略——接口留给 WP-22 调用。
- **通用热插拔事件队列。** 中断安全的 `oc_hotplug_post()`、进程上下
  文的 `oc_hotplug_drain()`、按设备类型或节点 ID 过滤的订阅、满队列
  丢弃计数。具体总线的触发逻辑归 WP-09a/WP-14a。
- **失败隔离。** probe 或 init 失败被记录（驱动名、错误码、次数、
  时间戳），节点以"未绑定＋错误码"保持可见，启动继续——绝不 panic、
  绝不阻塞后续驱动。`drv reload` 可重试，账目只在干净恢复后清除。
- **确定性初始化顺序。** 基于依赖声明的拓扑排序（Kahn 算法，优先级
  提示 + 名称决胜）——跨重启、跨重建逐字节一致，绝不依赖链接顺序。
  依赖环与缺失依赖被隔离并报告，而不是静默死循环。
- **`drv` / `dev` 诊断命令。** 两个总命令与十四个单独孪生命令共享
  同一实现（环 3 层把子命令映射到 L1SVC diag ops 40..51；内核侧负
  责全部渲染）——`drv list` 与 `drv_list` 逐字节一致。十六个命令全部
  注册、枚举并进入应用字典（现为 308 条）。
- **验证虚拟驱动放在 `tests/`。** `vtest-bus/ctl/mon/fail/cyc/late`
  在每次启动时走通全链路（注册 → 排序 → probe → 工作 → 移除 → 事件
  释放）；它们是测试脚手架而非内核驱动，树内已声明性质。
  `vtest-late` 是"零全局表修改"的活证据：在其余一切落地之后仅新增
  一个文件注册成功。

## 已知问题

- **K-04 —— `pmmrace` 可能导致内核 panic（既有缺陷）。** PMM 竞态
  探测器自身的竞态（位图与中断上下文分配器不原子）可能破坏在用物理
  页；已在上一版基线复现。本批次的启动工作移动了中断/循环相位，使
  致命交错更易命中。根治需要 PMM 的中断原子性——独立工作包。
- **K-05 —— 全新克隆可能轮换 OCIRE 密钥。** `ocire.mk` 在生成脚本
  mtime 晚于已提交密钥文件时会重新生成 Ed25519 公钥；轮换后的密钥
  已随本发布提交，git 与产物一致。
