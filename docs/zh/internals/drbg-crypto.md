# 内部机制：熵与加密核心

协议（TLS、SSH、OTA 校验器）所依赖的 RNG 与原语家族。
实现：`ocos/services/crypto/` ——
`interface/svc_crypto_{api,core,aead,bn,curve25519,ec_nist, rsa,sha512,x509}.h` 与对应的 `src/` 模块，外加
`src/svc_crypto_irq_window.h`、`src/svc_crypto_roots.h`
（生成）、`src/svc_crypto_dh_scale_vectors.h`。用法：
`cryptotest` / `dhtest`（L1 接口面*就是*测试面）。

## 1. DRBG（SP 800-90A HMAC_DRBG）

头注释（意图原文）："BUG-0106 (A4-02) 把旧的以定时器播种的
xorshift32 替换为 HMAC_DRBG（SP 800-90A）：CPU 提供时以
RDRAND 播种，否则以 RDTSC + 启动抖动重混，首次使用时实例
化并按需重播种。DRBG 状态由加密 IRQ 窗口保护
（BUG-0294、A4-07），因此并发 kthread 永远观察不到同一个
生成的块。"

实现事实：

- 状态：`static u8 drbg_k[32]; static u8 drbg_v[32]; static int drbg_ready;`
- `drbg_update` 实现 NIST SP 800-90A 第 10.1.2 节：
  `K = HMAC(K, V || 0x00 || data); V = HMAC(K,V); if data: K = HMAC(K, V||0x01||data); V = HMAC(K,V)`
- 熵收集 `drbg_entropy32`：RDRAND（经 CPUID 检查，
  `rdrand %0 ; setc %1`）每次 8 字节；回退路径混入
  `rdtsc_now()` 与弱源；与
  `rdtsc ^ (core_timer_ticks() << 1)` 的最终异或落在第
  24-31 字节。
- **重要性**（旧 xorshift32 灾难性地弱）："被动观察者
  可以计算出内核过去与未来生成的每一个密钥。SSH 服务器
  与 TLS 客户端实际上都是透明的。"
- RDRAND 包装器的 `setc` 标志是更严格的 CI 汇编器逼出来
  改对的 u8/"=q" 内联汇编约束 —— 见
  [../dev/portability.md](../dev/portability.md)。
- **IRQ 窗口**（`svc_crypto_irq_window.h`）：单核的一对
  save/cli/restore（`pushfq; popq %0; cli` /
  `pushq %0; popfq`），供惰性初始化器（AES 逆 S 盒、
  NIST 曲线表）使用，使并发 kthread 永远观察不到同一个
  生成的块或半成品表。宿主测试构建把它展开为空（文档化
  为构建环境属性 —— "不是 SMP 保护也不是锁"；内核是
  单 CPU 的）。

## 2. 原语家族

| 家族 | 成员 | 验证 |
|---|---|---|
| 哈希 | SHA-256（一次性 + 流式 `crypto_sha256_ctx{u32 h[8]; u64 total; u8 buf[64]; int buflen;}`）、SHA-384/512 | 经 `cryptotest` 的 NIST 向量 |
| MAC / KDF | HMAC-SHA-256（RFC 2104）、HKDF-Expand（RFC 5869）、TLS 1.3 密钥调度（RFC 8446 第 7.1 节：`net_tls13_ks_expand_label` / `derive_secret`） | NIST 向量 + RFC 8448 宿主测试 |
| 对称 | AES-128 块/CTR/CBC（FIPS-197）、AEAD：AES-GCM、ChaCha20-Poly1305 | RFC 8439 向量、NIST GCM TC3/4（宿主套件） |
| DH | 大整数模幂：固定 1024 位（`DH_BYTES 128`、Oakley Group 1、RFC 2409）+ 通用 `crypto_dh_modexp_n`（SSH group 14 2048 位）；内嵌 `crypto_dh_group1_prime/generator`、`crypto_dh_group14_prime[256]` | python3 pow() 金样本（规模扫描向量） |
| RSA | `svc_crypto_rsa.c`（TLS/SSH 的验证路径；`RSA_DEBUG` 是源码局部 `#ifdef`） | openssl 夹具（SKIP-FIXTURE 套件） |
| 椭圆 | NIST P-256 ECDH/ECDSA（`ec_nist`）、X25519（`curve25519`） | RFC 7748 向量、P-256 KAT（宿主套件） |
| 证书 | X.509 解析 + CA 链验证 + SAN dNSName 主机名检查（`x509`） | 真实站点链夹具（宿主套件） |

编号的 L1 扩展集对编码"保持封闭"（Driver-API 风格扩展）；
加密 L1 接口面恰好 2 个 op：`cryptotest`（op 1）与
`dhtest`（op 2），均以捕获方式运行。

## 3. 内嵌根 CA 存储

`src/svc_crypto_roots.h`："Auto-generated by
tools/embed_roots.py - DO NOT EDIT BY HAND. Embedded root
CA store (DER) for the X.509 chain validator." 原始 DER
字节数组（809 行的文件），覆盖公共根 —— 例如
`root_isrg_root_x1[]`（ISRG Root X1、4096 位 RSA、有效期
2015-06-04 -> 2035-06-04），外加 ISRG X2、GlobalSign、
GTS R1/R4、DigiCert、Baltimore、Amazon、Microsoft、
Sectigo E46/R46 根。TLS 客户端针对该存储验证服务器链；
自签名链默认被拒绝（`config set tls.insecure 1` 是显式
选择加入 —— HTTPS E2E 检查 0）。

## 4. 消费者

- **TLS 客户端**（`services/net/src/svc_net_tls.c`）：
  TLS 1.3（X25519 + AES-128/256-GCM + ChaCha20-Poly1305、
  完整 HKDF 密钥调度、加密握手、CertificateVerify）与
  TLS 1.2（ECDHE_RSA AES-GCM 0xC02F/0xC030、ChaCha20
  0xCCA8、legacy DHE AES-CBC 0x0067 回退；带 RFC 7507
  SCSV 的 TLS12 回退重试）。转录本 32768，溢出被标记
  （BUG-0078）；告警捕获 + 截断检测（BUG-0228）。
- **SSH 客户端/服务器**：KEX 首选
  curve25519-sha256（RFC 8731）/ 回退
  diffie-hellman-group14-sha256；主机密钥
  rsa-sha2-256/512 + ssh-rsa；加密首选 aes128-ctr /
  回退 aes128-cbc；hmac-sha2-256。宿主测试服务器
  （`tools/paramiko_sshd.py`）记录协商出的 DH 共享密钥
  K，用于与内核 `dhtest` 交叉核对。
- **OTA**：包 SHA256 校验器。

## 5. 测试面

- `cryptotest`（crypto op 1）：头部横幅
  `"Crypto self-test (NIST vectors):\n"`，然后逐原语的
  `    SHA-256: PASS` 风格行（SHA-256、AES-128、
  HMAC-SHA256、HMAC-SHA384）。
- `dhtest`（crypto op 2）：DH 模幂金样本测试 +
  ECDH/X25519 端到端检查（ok_e/ok_K PASS/FAIL 行）+
  `"DH modexp scale sweep (truth vectors, python3 pow()):\n"`。
- 宿主套件（`make test`）：AEAD/SHA（RFC 8439 + NIST）、
  bignum/P-256、X25519（RFC 7748）、RSA + X.509（openssl
  夹具，声明 SKIP-FIXTURE）、TLS 1.3 密钥调度
  （RFC 8448 + KeyUpdate KAT）、P0 TLS 批次
  （BUG-0022..0027，直接 include 内核 `net_tls.c`）、
  在全部四个 TLS 入口点的 A401 负长度 DER 探针。

## 6. 审计记录注记

两个著名的加密相关修复如今都有回归测试：TCP RX 校验和
链 bug（双重取反）与 TLS 握手中途主机名 bug。DRBG 替换
（xorshift32 -> HMAC_DRBG）是承重的那一个：内核生成的
每个密钥（SSH 会话密钥、TLS premaster secret）都源自
`crypto_random*`。

## 7. L1 接口面（2 个 op，均为捕获）

```c
#define L1SVC_CRYPTO_CRYPTOTEST 1   /* cryptotest              */
#define L1SVC_CRYPTO_DHTEST     2   /* dhtest                  */
```

- **触发**：开发者或回归门禁在 ush 提示符（或经
  `sysdiag` 的自检实验室 / `run` 机制）运行
  `cryptotest` / `dhtest`。
- **处理**：两者都经 `crypto_l1_dispatch` 路由进由
  `core_kcap_run_fn` 捕获的命令体，遍历向量表并逐原语
  打印 PASS/FAIL。
- **影响**：PASS 行是回归锚点（31 项门禁的检查 11）；
  这里 FAIL 意味着原语表或 DRBG 行为变了 —— 停止发布，
  先做 diff。

家族声明：
`OC_SERVICE_DECL_L1("crypto", "crypto service (aead/sha/rsa/dh/x509 + ring-3 surface)", 0, 0, crypto_l1_dispatch);`

## 8. 每个原语的消费位置

| 原语 | 消费者 |
|---|---|
| HMAC_DRBG（`crypto_random*`） | SSH 会话密钥、TLS premaster/traffic secret、任何 nonce |
| AES-GCM / ChaCha20-Poly1305 | TLS 1.3 记录保护；TLS 1.2 GCM 套件 |
| AES-CBC | HTTPS E2E 所钉住的 legacy TLS 1.2 DHE-RSA-AES128-SHA256（0x0067）回退 |
| SHA-256/384/512 + HMAC | 握手转录本、证书摘要、HKDF、DRBG 自身 |
| HKDF / TLS 1.3 密钥调度 | RFC 8446 第 7.1 节（`net_tls13_ks_expand_label`、`derive_secret`） |
| DH 模幂（group 1 / group 14） | SSH KEX 回退（diffie-hellman-group14-sha256）、legacy TLS DHE 套件 |
| X25519 / P-256 | TLS 1.3 + SSH curve25519-sha256 KEX；ECDH 自检 |
| RSA | TLS/SSH 服务器证书验证、ssh-rsa/rsa-sha2 主机密钥 |
| X.509 + 根存储 | TLS 客户端的链验证 + SAN dNSName 主机名检查 |
