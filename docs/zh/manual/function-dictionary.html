功能字典 — Open Cube OS 3.0.0 的全部命令 ​

本页是 3.0.0 用户面的完整、无遗漏索引： 296 条命令 = 284 个已注册程序 + 12 个 ush 内建命令。 下列每个程序都可以在 ush> 提示符下按拼写原样输入 （它位于内核注册表 OC_USERPROGS[] 中，由 tools/gen_userprogs.py 从 ocos/l1apps/ 生成）。

每条命令的详细说明位于 commands/（293 个页面， 每命令一页）。本字典补充了那些页面没有在每条目旁逐一写明的 内容：隐藏语法 —— 能够工作但注册表提示或 help 中没有展示的 flag、子命令与参数形式。

如何阅读本页 ​

标记含义
⚑隐藏参数面：该语法可用，但注册表提示、help 或应用自身的 usage 行没有提到它（或仅在某个子命令的 usage: 中提及）。
（无）该命令不接受参数（或其参数已被完整公示）。
destructive会破坏数据；向导用"重新输入设备名 + 裸 y 确认"加以防护，classic/direct 分发则立即执行。

12 个 ush 内建命令在此概述，完整文档见 ush-reference.md。测试/诊断桩（284 个中约 93 个） 有各自的深入页面：hidden-commands.md。

用户面从何而来 ​

  • 276 条历史命令已被回归门冻结 （tools/run_fix4_regression.py 测得注册表 ≥ 276；3.0.0 发布 284 条）。任何命令都不能被悄悄移除。
  • 8 个 mega 应用 在 3.0.0 中合并而成（update、disk-tool、 net-tool、sound-tool、files、sysdiag、hwinfo、power）； 历史的单命令应用仍保持注册，因此每个 op 至少有两种拼写 （见 mega-apps.md）。
  • ush 和 ld_so 已注册但从未是 v2.2.0 的 shell 命令 （标签 l1）。

help — 三种模式 ​

ush> help            built-in summary + "Registry: 284 programs - 'help -a'
                     lists them all, 'help -w' groups by work package."
ush> help -a         built-ins + every registry entry, A-Z, tagged
ush> help --all      (same)
ush> help -w         built-ins + registry grouped by work package;
ush> help --wp       the mega group renders FIRST

help -a 和 help -w 是多数用户从未发现的 flag；独立的 help 应用接受相同的 flag。行格式为 name [tag] hint（hint 跟随当前 locale，zh 回退到 en）。

mega (8) — 合并后的向导应用 ​

每个 mega 应用都有三扇门：无参数 → 交互式向导； <app> <op> [args] → classic 分发（与历史输出逐字节一致）； <app> direct <op> [args] → 逐字透传。字面词 direct 被跳过，其余部分到达历史 op。

命令用途隐藏 / 扩展语法
updateOTA 更新向导（5 步线性流程）⚑ update direct = 裸在线流程；⚑ update status / update --status — A/B 槽位 + 版本状态（打印 A/B disk: present 锚点）；⚑ update --local <path> / update local <path> — 从包 tar.gz 离线安装
disk-tool磁盘 / 文件系统向导⚑ direct 透传 30 个逐字 op 表（块 23 + 文件系统 7）：ahci, nvme, ata, dskstat, lsblk, parted, mkfs.fat32, mkfs.exfat, mkfs.ext4, fsck, sync, ahci_test, nvme_test, ata_dma_test, virtio_blk_test, disk_rw_test, partition_test, fs_mount_test, real_hw_test, abdisk, install, grub-install, abcfg, mount, mounts, umount, fatmount, fatstat, tree
net-tool网络向导⚑ direct 透传 16 个 op：arp, dhcp, dns, dnstest, firewall, ip, lspci, nf_test, route, tcpcc_test, tcpstats, tcptest, ssh, sshd, wifi, bt
sound-tool音频向导⚑ direct 透传 17 个 op：sound, hda, ac97, sb16, es1370, virtiosnd, usbaudio, play, volume + 6 个驱动自测 + audio_rw_test, sample_rate_test
files文件管理器向导（唯一 fork/execve 的 mega 应用）⚑ direct 启动真实程序：ls, tree, df, du, cp, mv, rm, edit, stat, chmod
sysdiag系统诊断向导⚑ direct 透传 46 个 op 行（含双词拼写 health export、health watch）；crashtest 只能通过 classic/direct 触达 —— 刻意不设为向导按钮
hwinfo只读硬件清单向导⚑ direct 透传 26 个只读 op（display/time/pci/acpi/usb/camera/input 家族）
power电源向导⚑ direct 透传 9 个 op：shutdown, poweroff, reboot, halt, sleep, poweroff_test, suspend_test, halt_test, reboot_test

direct 关键字在所有注册表提示中均未记载 —— 只在 各应用的 usage() 文本中记录。update、disk-tool lsblk 和 disk-tool direct lsblk 是同一服务 op 的三种等价拼写。

参数如何到达其语法 ​

上面大多数命令是服务 op 之上的薄封装，其参数处理方式 解释了几个令用户意外的行为：

  • 标准应用骨架（l1_lib.h、l1svc_main）将 argv[1..] 以单空格连接成一条 256 字节参数行， 通过 sys_l1svc(cat, op, arg, out, 32768) 发送， 并打印结果。因此多词语法（firewall add in drop tcp port 22） 按输入原样工作 —— 但超过 256 字节的部分会丢失。
  • 输出缓冲是静态 32 KiB。help -a 的完整注册表 列表（约 12 KiB）放得下；栈截断变体是很久前已修复的 bug。
  • rc 非零时封装打印 <app>: service call failed (rc=-1) — 284 个应用中约 150 个共享的这一模板（该 i18n 键总计被 250 个应用共享）。看到它时，真实情况在 dmesg 里：统一排查见 ../troubleshooting/error-catalog.md §7.1。
  • 少数命令不是封装：files 和 run fork+execve 真实 程序；ush、各编辑器以及平坦的 l1 探针自己做 系统调用。
  • dmesg 连接其 argv 时不加空格（单一 token）—— 出于 历史兼容保留的怪癖：始终用 dmesg 100，绝不要 dmesg -n 100。

help 不会强调的内容 ​

  • 上述 35 个隐藏面没有一个出现在注册表提示里。help -a 为每个程序打印一行提示；子命令语法只能通过 带一个错误参数运行该命令（多数会打印 usage: 行）或 阅读 commands/ 看到。
  • 测试桩（约 93 个程序）像其他命令一样列出 —— 没有任何标记表明它们是测试。它们可以安全运行，但少数 刻意制造破坏（crashtest、电源路径探针、 stackovf、badapp）；见 hidden-commands.md。
  • help -w 中的类别标签是历史产物，非语义（见上文 怪癖说明）。
  • fg/bg 出现在内建表中但未实现 （它们打印拒绝消息）；jobs 与 cmd & 是真实的。
  • 提示文本本身是双语的（每个应用的 i18n/{en,zh}.json 中的 _hint 键，构建时消费）； 缺失翻译是构建违规，因此你永远不会看到原始键作为提示。

运行时发现语法 ​

当你无法查阅本手册时：

  1. 带一个故意错误的参数输入该命令 — 多数语法会 打印其 usage: 行（crashtest x、watchdog x、logctl x、 firewall x、config x）。
  2. 先 help -w 找到家族，再用该家族的状态命令 （裸调用几乎总是状态形式）。
  3. 向导兼任语法教师：它们提出的问题与位置参数语法 一一对应（net-tool 的静态 IP 路径按 ip <a> <m> <g> 的确切顺序询问地址 → 掩码 → 网关）。
