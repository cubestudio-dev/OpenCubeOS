# 3.0.0-WP06g2 — L1 localization + the system IME

The l1_i18n batch: the ring-3 world goes bilingual, and Chinese input
becomes a system service.

## What changed

- **The i18n framework.** Every one of the 274 ring-3 programs carries
  `i18n/en.json` + `i18n/zh.json` (folder apps in `src/L1/<name>/i18n/`,
  legacy flat programs under `src/L1/_i18n/<name>/`). The resources
  compile into per-app key-sorted tables (`gen_userprogs.py`, strict
  gate - a missing resource fails the build); `_shared/i18n.h` provides
  the `tr_()` runtime (one `L1SVC DISP/LANG_GET` probe per process,
  zh-miss falls back to en, en-miss to the key). The L0 side keeps one
  shared table (`etc/i18n/l0/{en,zh}.json` → `tools/gen_l0_i18n.py`).
  Nothing is hardcoded: the sources say `tr_("key")`, the resource
  files carry the text.
- **`lang zh` is real now.** The historical zh columns of the five
  `lang` messages were English placeholders since the v2.2.0 rescue -
  they render real Chinese now. `help -a` shows the Chinese registry
  hints for all 274 programs; the shell built-ins, the file tools
  (usage/error sentences), `stat`, `free`, `ps`, `date` follow the
  zh_CN convention (translated sentences, English column skeletons).
- **The system IME.** One engine + one session live in the L0 display
  service (`ime_session.c`); editors drive it through the new
  `L1SVC_DISP_IME_BEGIN/KEY/END` ops (13/14/15, appended per the
  numbering contract) and never embed a copy. Candidates are
  phrase-first (622 hand-authored high-frequency words, pooled table),
  then the single characters (all 3755 level-1 hanzi), then one smart
  compose candidate (the first 2-3 segment exact-syllable split).
  Nine per page; PageUp/PageDown (or `-`/`=`) page; digits 1-9 pick;
  space picks first; Enter commits the raw letters; Esc clears.
  `ime -i` (the interactive console compose line) runs the same
  engine.
- **The editors.** `editor_core.h` is UTF-8 glyph-aware (character
  motion, whole-glyph deletion with exact cell wipes, multi-byte
  insert), gains `^K` cut / `^R` copy / `^U` paste, and F2 toggles
  the system IME (the compose strip renders on the status line).
  `vi` is modal for real: CMD mode (`hjkl`, `x`, `dd`, `yy`, `p`,
  `i/a/o`, `:w/:q/:wq/:q!`) over the same engine.
- **The make-all gap closed.** `userprogs_data.h` is a real make
  target (see KNOWN_ISSUES); the i18n json files ride the staleness
  set too.

## Live-caught on the way

The phrase pool had no NUL separators (the generator counted +1 but
never appended them - the whole library silently never matched); the
phrase binary search broke length ties in the wrong direction; the
smart compose outranked the real characters; `l1_l1_dispatch` never
NUL-terminated its rendering (strlen ran ~100 bytes into the heap
past every `help -a`); ush's own help buffer stayed 8 KiB; the serial
CSI table lacked the xterm F-key sequences (F2 was unreachable from
real terminals - raw 0x90..0x9B never arrives over serial).

## Verification

i18n battery 7/7, IME battery 3/3, editor battery 10/10, per-program
hints battery 4/4 (all 274 Chinese hints byte-scanned), the WP06g1
regression set (chinesetest 81/81, V4/V4b/V5, font audit 6763+682)
all green on the final image.
