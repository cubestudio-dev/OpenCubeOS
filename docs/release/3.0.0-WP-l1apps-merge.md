# 3.0.0-WP-l1apps-merge

The merged-app release: 200+ scattered commands gained an
intent-based front door, and the documentation was rewritten from
scratch for the era.

## The 8 merged mega-apps

`update`, `disk-tool`, `net-tool`, `sound-tool`, `files`, `sysdiag`,
`hwinfo`, `power` - each one app with three doors:

- **no arguments** - the intent wizard: single-key menus,
  auto-detection, cross-domain repair (the `update` wizard fixes a
  missing IP through DHCP and a missing A/B disk through
  `lsblk` + `abdisk` before it ever checks for updates), retype +
  bare-y double confirmation on every destructive path, fully
  bilingual (`lang zh` switches the whole wizard live).
- **`direct <op> [args]`** - explicit verbatim passthrough.
- **`<op> [args]`** - classic dispatch: the historical command
  spelling, byte-identical output.

Zero functionality loss: all 276 historical commands stay
registered (interface freeze; the regression gate enforces the
floor) - the registry now counts **284 programs** (+ the 12 ush
built-ins = 296 commands).

## What shipped

- `ocos/interface/wizard_lib.h` - the shared wizard primitives
  (L1SVC capture, anchor probing, READLINE asks, single-key menus,
  y/N confirms).
- 8 app folders under `ocos/l1apps/` (update replaced in place) +
  bilingual i18n resources for each.
- `help -w` grows the leading **mega** group (the 8 apps), l0 i18n
  keys for it.
- The update wizard's 5-step chain: network -> A/B disk -> DNS
  (host parsed from the live `config get update_url`) -> check
  (up-to-date exits OK) -> confirmed install + confirmed reboot.
- Guarded destructive paths: mkfs.*, abdisk, install, rm, the power
  actions (wizard only - classic/direct stay verbatim for scripts).

## Documentation, rewritten from scratch

- **User manual** (en + zh): the 8-app surface map, the new
  mega-apps guide, getting-started through the wizards, honest
  command surfaces everywhere (`ush>` prompt era, 284-command
  registry).
- **Developer set** (en + zh): the ring-3 app development guide -
  app anatomy, the L1SVC surface map with the output-anchor
  contract, the wizard library, a complete writing-an-app tutorial,
  service family pages rewritten for the ocos/ tree.
- **Maintainer set** (en + zh): troubleshooting through the
  mega-apps, the gh-pages website flow, this release's notes.
- Command reference pages regenerated from the live registry
  capture (292 pages, en + zh, the 8 mega-app pages included).
- `tools/gen_api_docs.py` modernized: current tree paths
  (ocos/l1apps), the WP06g2 registry row format (`name [tag] hint`), serial-echo tolerance, the v1 baseline fallback wired to
  `evidence/v1_command_list.txt`.

## Compatibility

- Every historical command name still resolves (freeze enforced).
- `update` with no arguments now opens the wizard; the historical
  bare-`update` online flow is `update direct` (or any argument
  shape, verbatim as before).
- Service output lines are unchanged - the English anchors the
  wizards and scripts probe (`"A/B disk: present"`, `"New version available."`, `"DHCP success: IP="`, `"DNS resolution failed"`,
  `"reboot required"`) are part of the contract.
