# Tree map: what every directory is, and why it exists

A layer-by-layer reading of the repository. Every directory below has a
one-paragraph answer to two questions: **what is inside** and **why does
it exist**. The system-level view of the four components is
[system-map.md](system-map.md); this page is the file-tree counterpart.

```
ocos/
  Makefile  include/  etc/  evidence/  website/  docs/  tools/  tests/
  .github/  grub.cfg  grub-ab.cfg
  ocbl/   <- boot loader            (BIOS + UEFI flavors)
  ocire/  <- recovery kernel        (independent L0 peer)
  ocse/   <- install environment    (vendored from v1.0.0)
  ocos/   <- the main system        (kernel + drivers + services + L1 apps)
```

## Root directory

| Entry | What it is / why it exists |
|---|---|
| `Makefile` | The WP-13 build composition root. `OC_RELEASE_VERSION ?= 3.0.0-NAK` (line 90) and `OC_KERNEL_BUILD ?= git rev-list --count HEAD + 21` (lines 103-104) are the single version source every component consumes (see [system-map.md](system-map.md)). Targets: `make`/`kernel` (ELF), `all` (kernel + ISO + src zip + OTA), `iso`, `run-bios`/`run-uefi`/`shot-*`, `reproducible-check`, `dist`, `clean`. Includes the per-component makefiles in dependency order: `ocire/ocire.mk` -> `ocbl/ocbl.mk` -> `ocse/ocse.mk`. Also carries the `ARCH` dispatch (`x86_64` default; `arm64`/`riscv` build the bring-up shells only). |
| `ARCHITECTURE.md` | The root architecture statement: the two rings (L0 provides services / L1 uses services), component inventory, pointers to `docs/data/stats.json` (regenerated by `make api-docs`). |
| `README.md`, `BUILDING.md`, `CONTRIBUTING.md`, `FAQ.md` | The standard front-door documents (also mirrored under `docs/root/`). |
| `INTERFACES.md` | The historical interface register (numbered L1 extension surface 1-138 era); the live ring-3 contract is `ocos/interface/` ([private-headers.md](private-headers.md)). |
| `KNOWN_ISSUES.md` | Declared, deliberate limitations (e.g. "#DF panic is minimal by design"). |
| `bug-list.md` | The 3.0.0 defect census: 141 GitHub issues + the WP-06h audit findings, exported for the fix work packages. |
| `VERIFICATION_REPORT.md`, `MANIFEST.md`, `ARCHIVE-README.md` | Release evidence: verification transcript, shipped-file manifest, and the pointer readme for archived material. |
| `LICENSE`, `NOTICE` | Apache-2.0 text and attribution notice. |
| `build.ps1` | Windows PowerShell build wrapper (the primary path is the Makefile). |
| `grub.cfg` | The **removable/ISO medium** GRUB menu (pre-OCBL era, still shipped for GRUB-booted media): loads the gfxterm/font/serial module stack, implements the A/B flag selection on `(hd0)`, offers slot A/B/ISO entries, attaches the kernel ELF as the `self` module. |
| `grub-ab.cfg` | The **installed A/B disk** variant of the same selection logic - minimal (no gfxterm, no ISO fallback), refreshed by every update install as `/boot/grub/grub.cfg` on partition 1. It sits at the repo root because three top-level trees include it and none of them may own it. |
| `etc/` | Host-side configuration inputs baked into images: `opencube.conf` (the default `/etc/opencube.conf`: update_url, auto_check, package_url, log.level, serial_encoding, pmtimer.width...) and `i18n/l0/{en,zh}.json` - the L0-side i18n tables that `tools/gen_l0_i18n.py` compiles into `ocos/kernel/core_lib_i18n_data.c`. |
| `evidence/` | Frozen acceptance transcripts: `help_a_runtime.txt` (the full `help -a` registry listing captured live) and `v1_command_list.txt` (the v1.0.0 command inventory kept for parity checks). |
| `website/` | The project site (`index.html`, `about.html`, `architecture.html`, `download.html`, assets, CNAME) plus `public/downloads/` - the update artifacts the in-OS `checkupdate` actually fetches, and `public/update.json` / `update-v2.json` (the OTA manifests). |
| `docs/` | The documentation tree (below). |
| `tools/` | 117 build/test/maintenance files (below). |
| `tests/` | 48 host-side test files (below). |
| `.github/workflows/build.yml` | CI: builds the full WP-13 pipeline (`make all`) under the zero-warning gate (`-Wall -Wextra -Werror`, enforced by every component's makefile), verifies the artifacts, and checks `make clean` leaves nothing behind. |

## `ocos/` - the main system

### `ocos/kernel/` - the L0 core (flat, 55 entries + `arch/` + `generated/`)

Naming law: every file is `core_<area>_<name>.(c|h)` in one flat
directory - the historical `kernel/core/`, `kernel/mem/`, `kernel/lib/`
paths survive only in "File:" header comments. The areas:

| Prefix | Files | What the area owns |
|---|---|---|
| `core_boot_*` | `entry.S`, `longmode.S`, `mb2header.S`, `main.c` (751 lines, the kmain composition root), `state.c` (boot-state monitor, kernel side), `grubstub.c`/`grubdata.h` (two-stage GRUB embed), `selftest.c` (L1 extension canary), `l1launch.c` (spawns ush) | Boot: multiboot2 entry, 32->64 transition, the hand-curated bring-up sequence |
| `core_mm_*` | `pmm.c` (bitmap PMM), `vmm.c` (4-level page tables), `heap.c` (free-list heap) | Memory management - [memory.md](memory.md) |
| `core_sched.c` | | 32-slot preemptive priority+RR scheduler - [scheduler.md](scheduler.md) |
| `core_sync.c` | | spinlock/semaphore/mutex/condvar |
| `core_timer.c` | | PIT @ 100 Hz, ms tick, 16-slot soft timers |
| `core_usermode.c` | | syscall table + `int 0x80` dispatch, ELF64 loader (static + ET_DYN + ASLR), fork, signals, unified reaper - [syscall-ring3.md](syscall-ring3.md) |
| `core_kcap.c` | | kernel output capture - THE load-bearing path of the L1SVC text surface ([hidden-mechanisms.md](hidden-mechanisms.md)) |
| `core_registry.c` | | the `.oc_apps` L1-application registry collector |
| `core_console_*` | `fb.c`, `font.c`, `font_data.c` (generated by `tools/gen_font.py`), `screen.c` | framebuffer primitives, 8x16 font, text-grid console with the single output-hook slot |
| `core_lib_*` | `config.c` (/etc/opencube.conf store), `gzip.c` (RFC 1951/1952 inflate), `i18n.c`+`i18n_data.c` (L0 i18n), `klog.c` (4-channel kernel log), `log.c` (boot stage logger), `string.c`, `tar.c` | the freestanding runtime library |
| generated | `userprogs_data.h` (27k lines: **284 gzip'd ring-3 programs** + the `OC_USERPROGS[]` registry, from `tools/gen_userprogs.py`), `solib_data.h` (embedded ld.so + libfoo.so), | the build's generated payload |

`ocos/kernel/arch/x86_64/` is the real architecture: `arch_idt.*`,
`arch_exceptions.*`, `arch_irq.*`, `arch_lapic.*`, `arch_pic.h`,
`arch_multiboot2.*`, `arch_context_switch.S`, `arch_enter_ring3_fork.S`,
`arch_exc_exit.S` (the IST2 exit stack), `arch_abi_probe.S`,
`arch_acpi_s3*.S`, `linker.ld` (with the `.oc_drvs/.oc_svcs/.oc_apps`
section boundaries and the `__end_of_kernel <= 0x400000` ASSERT).
`arch/riscv/` and `arch/arm64/` are WP-13 bring-up shells (UART banner +
WFI heartbeat, parks secondary harts) - not full kernels, honestly
labeled. `kernel/generated/` holds `version_gen.h` (the
`OC_VERSION_STAMP` recompile trigger), `config_gen.h` (the
`OC_CONFIG_NVME/AHCI/VIRTIO_BLK` WP-13 config gate) and
`grub_boot_data.c` (the 1 MB embedded GRUB stage-2 payload).

### `ocos/services/` - 24 families + `svc_framework.{c,h}`

Each folder owns one L1SVC category (or is a kernel-only mechanism
owner). The framework (`OC_SERVICE_DECL`/`OC_SERVICE_DECL_L1` placing
descriptors into `.oc_svcs`, `svc_framework_collect()` into a 64-entry
table) is documented in [hidden-mechanisms.md](hidden-mechanisms.md);
the full category/op numbering is
[syscall-ring3.md](syscall-ring3.md). Families and their categories:
`time`(1), `block`(2), `net`(8) + `nic`(3), `audio`->`snd`(4), `power`(5),
`selfhost`->`ota`(6), `fs`(7), `health`(9), `klog`(10), `watchdog`(11),
`crypto`(12), `l1`(13), `display`(14) + `input`(15), `camera`(16),
`usb`(17), `ocembed`->`ocire`(18), `diag`(19), `tui`(20) - plus the
kernel-only mechanism owners `crash`, `encoding`, `font`, `ipc`,
`loader`, `sysapi`. 220 files, ~67k lines; the ring-3 surface totals
208 ops over 20 categories.

### `ocos/interface/` - the 8 private ring-3 headers

`crt0.asm`, `oc_l1_api.h`, `l1_lib.h`, `l1svc_ops.h`, `fs_lib.h`,
`i18n.h`, `wizard_lib.h`, `editor_core.h` - the ONLY header set a
ring-3 application may include (enforced at build time by the L1 compile
`-I` path). Dedicated page:
[private-headers.md](private-headers.md).

### `ocos/l1apps/` - 284 embedded ring-3 programs

One command = one app = one folder with a `main.c` + `i18n/{en,zh}.json`
(252 folders, of which `_i18n/` holds shared tables; the registry count
is `OC_USERPROGS_COUNT = 284`). Categories visible in the tree: the
`ush` shell and its builtins; per-device status commands (`ahci`, `hda`,
`e1000e`, `wifi`...); the `*_test` batteries (50+); the 8 merged
mega-apps (`update`, `disk-tool`, `net-tool`, `sound-tool`, `files`,
`sysdiag`, `hwinfo`, `power`) built on `wizard_lib.h`; the editors
(`nano`, `vi`, `edit` sharing `editor_core.h`); text tools (`cat`,
`grep`, `sed`, `awk`, `sort`, `wc`...). Plus ~34 flat top-level sources:
the legacy `.asm` test programs (`fork_test.asm`, `g6_*.asm`, ...), the
dynamic-link test set (`ld_so.c`, `libfoo.c`, `main_dyn.c`,
`pie_test.c`) and `user.ld` (the ring-3 link script, load address
0x400000). Why one folder per app: `tools/gen_userprogs.py` walks the
tree, compiles each folder against `ocos/interface/` only, gzip-compresses
the ELF and appends it to `userprogs_data.h` with a bilingual hint
([hidden-mechanisms.md](hidden-mechanisms.md) explains the lazy inflate;
[../l1/app-anatomy.md](../l1/app-anatomy.md) the app shape).

## `ocbl/` - the boot loader (59 files)

Three backends around one firmware-agnostic core:

| Folder | Files | Content |
|---|---|---|
| `bios/` | 16 | `stage1.asm` (the 512-byte sector, two flavors from one source: `-D OCBL_ELTORITO` / `-D OCBL_MBR`), `core_head.S` (32->64 core entry, identity page tables at 0x8F000, EBDA guard), the real-mode trampoline pair, int 10h/13h/14h/15h/16h/1Ah backends, VBE, RSDP scan, VBR chainload |
| `efi/` | 10 | the freestanding UEFI type definitions (no EDK2), `efi_entry.c` (MS-ABI entry, fixed-window reserves, EBS retry loop), BlockIo disk backend, GOP, GetMemoryMap->E820, EFI chainload, the 64->32 handoff blob |
| `common/` | 23 | the six-class scanner, the read-only FAT12/16/32+ISO9660 volume layer, MBR/GPT traversal (incl. the 0xEE shadow case), the ELF loader + mb2 builder, the 3-key menu, the boot-state monitor, ACPI S5, the 6300ESB watchdog, polled 16550 serial, and the flavor contract headers |

Top level: `ocbl.mk` (all make targets), `linker_bios.ld` (core at
0x7E00), `linker_efi.ld` (intermediate ELF at 0x11000), and the Python
build pack: `build_image.py`, `build_test_iso.py` (the ISO packer for
ALL ISOs - dual El Torito, G13 determinism, deliberately no
`-boot-info-table`), `elf_to_efi.py`, `make_scan_disks.py` (the 8-image
scanner test fleet), `make_chain_disks.py`, `menu_drive.py` (QEMU
monitor sendkey driver), `qemu_snap.py`. Deep dive:
[boot-flow.md](boot-flow.md).

## `ocire/` - the recovery kernel (49 files)

A flat source tree (own everything: `ocire_ata.c`, `ocire_fat.c`,
`ocire_sha256.c`, `ocire_console.c`, `ocire_idt.c`, `ocire_acpi.c`,
`ocire_wdt.c`, ...) plus three special corners:

- `ocire/agent/ocire_agent.c` - the ring-3 log agent, compiled like an
  l1apps program (freestanding + `ocos/l1apps/user.ld` @ 0x400000 +
  `int 0x80`), shipped as a standalone ELF on the recovery volume and
  injected at kexec as the protected `ocire_guard` process. It lives in
  its own subfolder because it is the one OCIRE file that builds against
  the OCOS ABI.
- `ocire/generated/` - `ocire_version_gen.h` (the `OCIRE_STAMP` banner)
  and `ocire_cn_font_data.c` (generated from OCSE's font data by a sed
  include-rewrite rule, so font re-vendorings flow in automatically).
- `ocire/grub-dual.cfg.in` - the template for the one remaining GRUB
  chain (the dual-boot repair-target disk), with `@KERN_LBA@`/
  `@KERN_SECTORS@` blocklist placeholders filled by
  `tools/make_ocire_disk.sh`.

Plus `ocire_bootsvc.c` (the supervisor decision loop), `ocire_kexec.c` +
`ocire_kexec_jump.S` (the OCOS re-launch), `ocire_shell.c` /
`ocire_recover.c` (the bilingual recovery shell: `logread`, `syscheck`
ten-point integrity check, `repair quick|full`, `return`, `shutdown`,
`reboot`, `lang`). Deep dive: [../dev/ocire.md](../dev/ocire.md) and
[crash-recovery.md](crash-recovery.md).

## `ocse/` - the install environment (179 files)

**Vendored from git tag v1.0.0** (commit bdc47047, the last
pre-restructure monolithic kernel - 143 vendored files under
`ocse/{kernel,drivers,fs,l1,boot,chinese}`). Why vendored: OCSE runs
before any OCOS service exists, v1.0.0 already contained every driver
an installer needs, and a frozen copy keeps the installer bootable as
the main kernel evolves. The re-vendor + patch loop:
`tools/vendor_ocse.sh` (PRESERVE list keeps OCSE-native files like the
PS/2 mouse driver) + `tools/ocse_edits.py` (edits **E1-E20**, the only
sanctioned way the vendored base changes - never hand-edit
`ocse/{kernel,drivers,fs,l1,boot,chinese}/*.c`). The edits strip what
an installer must not have: E1 OTA/update API, E4/E5/E6 ring-3
crash/kill/int 0x80 (no user plane), E7 USB MSC/serial pollers, E12
replaces the OC_DRIVER_DECL collection with direct calls from the
24-stage boot ladder. On top of the vendored base sit the OCSE-native
pieces: `ocse_main.c` (mode loop GUI<->CLI), `ocse_cl.c` (OCSECL,
1919 lines, 40 commands), `ocse_gui.c` + `ocse_wizard.c` +
`ocse_wzctl.c` (the 9-step wizard + widget toolkit), `ocse_inst.c` (the
installer engine: OCBL MBR writer + the 8-step install state machine),
`ocse_mkfs.c` / `ocse_ext4w.c` (real FAT32/exFAT/ext4 formatters, ext4
even writable), `ocse_atapi.c` / `ocse_iso.c` (the install medium),
`ocse_detect.c` (the four hardware checks), `ocse_i18n.c`, and
`linker_ocse.ld` (1 MiB base, the `.ocsework` NOLOAD wizard-state zone,
the same 0x400000 ASSERT). [boot-flow.md](boot-flow.md) covers the
handoff; the E1-E20 list is `ocse/VENDORING.md`.
