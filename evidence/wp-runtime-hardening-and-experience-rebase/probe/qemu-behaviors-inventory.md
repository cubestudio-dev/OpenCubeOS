Generated by tools/probe/qemu_behaviors.sh from the four raw

## 探测方法

- BIOS 轨：一个 512 字节的 El Torito 裸机探测扇区（tools/probe/probe_bios.asm），
  从 SeaBIOS 手里接过的机器状态原样经串口转储。
- UEFI 轨：一个独立的 BOOTX64.EFI 探测应用（tools/probe/probe_uefi.c），
  转储 EFI 应用入口的机器状态（GDT/IDT、CR0-4、EFER、页表统计、PIC/IOAPIC）。
- 严格模式参数（规约 4.3）：`-cpu qemu64,enforce -machine vmport=off -boot strict=on`。

## 行为 → 拉平措施对照

| # | 观察到的固件/QEMU 行为 | 拉平措施（OCRMECL） |
|---|----------------------|---------------------|
| 1 | BIOS 轨引导扇区入口的 GPR/FLAGS/段寄存器各固件不同（见上方转储），且不可依赖 | OCBL stage1 本就不读它们（入口形态检测 + 自建栈）；OCRMECL stage1 同样只用 DL |
| 2 | GDTR/IDTR 是固件遗留（SeaBIOS 留实模式 IVT 描述符；OVMF 留 64 位表） | OCRMECL 建自有 256 门 IDT（BIOS@0x2000 / UEFI 镜像内），任何向量在 OCBL 接管前落到标记停机存根，不再继承 |
| 3 | A20 状态不保证 | OCRMECL 强开（int15h 2401 → 0x92）+ 双图案验证 |
| 4 | 8259A 掩码/向量是固件自定 | OCRMECL 重映射至 0x08/0x70 并全掩蔽 |
| 5 | IOAPIC RTE 状态是固件遗留 | OCRMECL 全 RTE 掩蔽（unreal-mode MMIO） |
| 6 | UEFI：CR3 页表带 NX/RO 限制（见 PML4 统计行），且固件把页表页自身映射为只读 | OCRMECL 剥离全部 present 项的 NX、置 RW（WP 临时关闭绕过页表自保护） |
| 7 | UEFI：boot services 存活时的中断生态（OVMF 定时器/输入事件） | OCRMECL 调用 ExitBootServices 切断一切固件服务后移交 |
| 8 | QEMU 对未实现特性静默降级（默认 cpu 无 enforce） | 严格矩阵（make test-strict）以 enforce 参数暴露差异，启动链不依赖任何非默认特性 |
| 9 | vmport（0x5658）默认存在，可被探测为 VMware 环境 | 严格矩阵 vmport=off 验证启动链不触碰该端口 |
| 10 | -boot 默认带回退行为 | 严格矩阵 strict=on 验证无引导介质回退依赖 |

## 结论

两轨在默认与严格参数下的启动链（证据见 regression/ 目录）均不依赖上述任何
保姆行为：OCRMECL 在 OCBL 之前把机器状态拉平为清单所列的确定性契约
（interface/boot_handoff.h）。
