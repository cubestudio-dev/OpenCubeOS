WP-08 asset re-cut + rebuild verification (2026-11-19)
======================================================

Context: the original release build host was lost before the Release
was published.  The assets below were re-cut on a fresh toolchain
(qemu-system-x86 10.0.13, nasm 2.16.03, xorriso 1.5.6, grub 2.12,
system gcc 14.2.0 - the release compiler) from the tree at main
bbfb0820 with the local tag v3.0.0-WP08-driver-framework (= the
shipped tree, pool fixup included), version overrides
OC_RELEASE_VERSION=3.0.0-WP08-driver-framework OC_KERNEL_BUILD=477.

The OCIRE key anchor was preserved (the committed key compiles in;
the K-05 mtime lottery on a fresh clone was defused by touching the
generated anchor after checkout).

  fc97d4b2 tree).  The re-cut follows the tag (= bbfb0820) so the
  delivered source is the exact source of the shipped binaries
  (#138 spirit: the zip must not diverge from the release).  The
  30224a08 cut was itself reproduced bit-exactly before re-tagging
  (proof the recorder cut from fc97d4b2, and that git-archive cuts
  are deterministic).
- OTA tar.gz: tar member mtimes + gzip header mtime + the manifest
  "time" date are baked in per cut, so container bytes cannot be
  reproduced by construction.  The payload is stable: the manifest
  payload digest (concatenated file bodies, archive order) is
  a92326173a625aa23d3603e6ead952ed51e5672d7f5de57bc4aab112f61a09e5
  on every cut, and the kernel ELF it carries is the byte-identical
  one embedded in the proven ISO.  update.json now records the

- build number: the shipped kernel banner is build 477 (evidence 05

3. K-05 consequence recorded
----------------------------
The private half of the Ed25519 keypair anchored in this release
existed only on the lost build host.  No release asset depends on a
signature (the OTA flow uses the sha256 manifest), but OCIRE-signed
update payloads for THIS anchor are not producible; the next `gen`
rotation re-anchors.  See the K-05 entry in the release notes.
