Open Cube OS 3.0.0-WP05 OCBL - B2a: BIOS services trampoline evidence
====================================================================
Test: QEMU SeaBIOS boot of build/ocbl/ocbl_test.iso with a control
      hard disk (known magic EB 'XXCTRLHD' + 0xAA55) attached.
      qemu -cdrom ocbl_test.iso -drive if=ide,format=raw,file=ctrlhd.img
Date: 2026-10-30 11:53 UTC

What is proven (serial transcript below, verbatim):
  1. 64->32->16 real-mode trampoline round trip (16+ full cycles per
     boot; every BIOS call below went through it)
  2. int 15h AX=E820 memory map: 6 real entries, [0] 0..0x9FC00 usable
     (the canonical QEMU/SeaBIOS map - matches what GRUB sees; the
     trailing zero-length entry is the SeaBIOS terminator quirk,
     stored but filtered from display)
  3. int 13h AH=48h geometry: hd 0x80 = 2048 sectors x 512 B,
     cd 0xE0 = 2048-B sectors (total -1 = unknown, CD semantics)
  4. int 13h AH=42h extended reads: hd 0x80 LBA 0 returns the
     control disk magic 'EB 58 58 43 54 52 4C 48'; cd 0xE0 LBA 16
     returns the ISO PVD ('CD001', type 1); cd 0xE0 LBA 34 returns
     our own El Torito image's first bytes (FA FC 31 C0 8E D0 BC 00
     = the stage1 entry code)
  5. int 13h AH=02h classic CHS read verified on the control disk

Live-caught traps fixed on the way (all reproduced -> root-caused ->
fixed -> re-verified, root causes recorded in the source comments):
  T1 16-bit code segment truncates 32-bit far-jump offsets -> the
     trampoline's code16/data16 descriptors got BASE=0x40000 (GRUB
     avoids this only because its trampoline lives below 64 KiB)
  T2 DAP byte-layout mis-mapping (block count is u16[1], not u16[2])
     -> the BIOS 'transfers' zero blocks and reports success: CF=0,
     AL=0, buffer untouched - found via a 0xEE-prefill canary
  T3 E820 scratch slot landed exactly on entries[0] (the array starts
     at BUF+8 because of u64 alignment) -> every call corrupted the
     map; moved to a separate 0x61000 scratch
  T4 continuation-id and SMAP-echo mishandling in the E820 loop
  T5 the self-patch INT opcode byte was clobbered by a debug probe
     placed between the label and the instruction
