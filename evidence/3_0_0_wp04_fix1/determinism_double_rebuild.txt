Open Cube OS 3.0.0-WP04-fix1 - ISO determinism restored (audit finding)
========================================================================
Found during the fix1 re-verification (declared per the fix1 spec:
found = fixed on the spot):

SYMPTOM
  The WP-05 OCBL packer (ocbl/build_test_iso.py) claims the G13
  determinism stack is "delegated" to it, but two FORCED rebuilds
  minutes apart produced ISOs differing in exactly:
    - the PVD root-record mtime + every directory-record mtime
      (minute/second fields) - the staging tree is recreated per
      build, and --set_all_file_dates pins FILE nodes only;
    - the Rock Ridge TF atime of DIRECTORY nodes - xorriso touches
      the source directory atimes while walking (after any pre-touch),
  The G13 stack had this fixed (make-iso: find -exec touch -d @0);
  the WP-05 packer rewrite dropped that step.  (The naive same-minute
  double build stays identical - the stamps only drift across
  minutes; that is how it slipped through.)

FIX (ocbl/build_test_iso.py + tools/iso_zero_ctime.py)
  1. pin the whole staging tree mtimes to the epoch before xorriso;
  2. zero the RR TF ctime post-build (the G13 walker, now wired into
     the packer);
  3. extend the walker to also zero the RR TF atime (directory leak).
