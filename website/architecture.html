Architecture

How the machine is put together: the L0/L1 split, the boot flow, every kernel subsystem, the TUI desktop, and the 162-interface extension surface. Everything below is read straight from the tree.

Two layers by design

L0 is the complete kernel plus the recovery shell (this repository). L1 is everything built on the extension surface - L0 ships without any.

l0

L0 - the kernel and the recovery shell

Boot, memory, scheduling, ring-3, VFS, networking, drivers, TUI, crash recovery, OTA. 140,672 lines across 353 source files, zero external runtime dependencies.

l1

L1 - the extension ecosystem

Modules loaded as shared objects or compiled against the surface headers. 162 numbered interfaces in 13 surface headers is the whole contract.

why

Why split at all

A recovery-first kernel must stay minimal and trustworthy; user-facing growth happens above it. The oc> shell always works, even when everything above fails.

Boot flow

From power-on to the shell prompt - both firmware paths, measured on every release.

1

GRUB 2.12 - hybrid BIOS + UEFI

One ISO image carries both boot paths. GRUB hands over the machine via multiboot2 and attaches the kernel ELF as its own install payload.

2

boot/boot.S - the 32-bit trampoline

Entry at 0x100000, builds the GDT, maps the first 2 MiB identity, switches paging on and jumps to 64-bit long mode - 16 assembly screens of exactly that.

3

kernel/main.c - bring-up

One OK line per subsystem: multiboot2 handshake, framebuffer, IDT + IST exception stacks, PIT at 100 Hz, PMM over the memory map, then drivers, VFS, network, shell.

4

oc> - the recovery shell

233 commands over pipes, redirection, jobs and scripting; A/B slot menu when an update is staged; help -a lists everything alphabetically, help -w by work package.

Every release gates on this exact sequence booting clean in QEMU twice - legacy BIOS and UEFI (OVMF).

The TUI desktop

A real desktop environment on the raw framebuffer - no GPU stack, no compositor, just the kernel renderer.

desktop

Desktop + taskbar

Window list, running apps, clock, system tray area - driven from the framebuffer console the kernel itself renders.

apps

Apps, menus, forms

Menu system, form widgets, a full-screen editor and the system apps (system info, network, hardware) - 9 TUI commands in the shell.

cjk

Chinese console + IME

A dedicated CJK layer: 16x16 bitmap font, GB2312/UTF-8 codecs and an interactive pinyin IME (ime -i) on both the console and the TUI.

render

One renderer, three outputs

The same cell grid renders to the VGA text buffer, the linear framebuffer and the TUI - font engines are swappable through the L1 surface.

Reliability mechanisms

A recovery shell is only credible if the kernel can survive its own failures - these are the mechanisms, all testable from oc>.

dump

Crash dumps

Register dump to serial on exception; crashlog persisted to the /etc volume; crashlog replays the last failures after a reboot.

wdt

Hardware watchdogs

Intel TCO and ACPI WDAT timers, armed for real - the E2E suite proves a hard reset and a clean second boot. Policy watchdogs kill starving tasks first.

klog

Kernel log

Ring buffer with levels and filters, generation-rotated files (kernel.log, kernel.log.1), dmesg on the serial console.

health

Health monitoring

CPU / memory / task / IO sampling with alarms (CPU-LOCKED at 90%+), JSON export through the L1 surface.

Cross-platform build

One tree, three architectures, two host OSes - and it is reproducible.

make

make all, one command

Kernel, ISO, deterministic source zip and OTA package from a clean tree - tools/build.sh detects or installs the toolchain, build.ps1 covers Windows (WSL2 / MSYS2).

repro

Reproducible by design

SOURCE_DATE_EPOCH-driven archives; the same commit rebuilds the same bytes - the CI pipeline gates every push on it.

cross

ARM64 + RISC-V cross targets

Real bare-metal bring-up shells (PL011 / NS16550A serial, CNTPCT / CLINT timers) that print the banner and heartbeat in QEMU - same tree, different arch.

config

Fast and configurable

Content-addressed object cache (measured 3.2x on a warm build), make menuconfig with defconfigs, and CONFIG_TUI=n builds a 216-command minimal system.
