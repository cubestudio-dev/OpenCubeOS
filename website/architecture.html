Architecture

How the machine is put together at 3.0.0-WP06f: the L0/L1 split, the OCBL boot flow, every L0 subsystem, the 275-program L1 world, and the 20-service SYS_L1SVC surface. Everything below is read straight from the tree.

Two layers by design

L0 is a pure service kernel: kernel + drivers + root services + the numbered interface, and nothing else - no shell, no commands, no TUI, no input method (the 2.x recovery shell was removed in WP-03). L1 is the whole user world in ring 3, and 3.0.0 ships both in one tree under src/L0/ and src/L1/.

l0

L0 - the pure service kernel

Boot, memory, scheduling, ring-3, VFS, networking, drivers, crash machinery, OTA - laid out as src/L0/boot/ core/ drivers/ services/. 128,890 lines across the tree, zero external runtime dependencies, zero interactive user surface: no shell, no commands, no TUI, no IME live in L0.

l1

L1 - the ring-3 world

275 programs under src/L1/ (242 app folders + 8 flat .c + 25 flat .asm): ush, the TUI desktop, the editor, the Chinese console + pinyin IME, and one command per app - 285 commands = 274 registry apps + 11 ush built-ins, all served through the 20-service SYS_L1SVC surface (190 numbered entries).

why

Why split at all

A service kernel must stay minimal and trustworthy; user-facing growth happens above it. The kernel self-tests, watchdog, crash policy and log readers stay in L0 as services; if the ring-3 world cannot start, L0 says so honestly and halts - the guidance is a reboot or the OCBL boot menu (there is deliberately no L0 shell to fall back to).

Boot flow

From power-on to the ring-3 ush prompt - both firmware paths, measured on every release. No GRUB anywhere in the 3.0.0 chain.

1

OCBL - the self-written bootloader

One ISO carries both paths: a 512-byte real-mode stage 1 (El Torito / MBR) for legacy BIOS, and an EFI entry for UEFI. OCBL scans the disks dynamically, shows a boot menu with a 10 s countdown, then loads the OCOS kernel and enters long mode itself - 16-bit → 32-bit → 64-bit.

2

src/L0/boot/ - the 64-bit entry

boot.S builds the GDT, maps the low identity range, switches paging on and jumps to 64-bit C code; kmain is the first C entry. The BIOS flavor arrives here from OCBL's core head; the UEFI flavor has its own EFI entry that calls the same C bring-up.

3

kmain - L0 bring-up

One OK line per subsystem: IDT + IST exception stacks, PIT at 100 Hz, PMM over the memory map - then the declared drivers and services are collected from their link sections (OC_DRIVER_DECL / OC_SERVICE_DECL) and initialised, ending at crash recovery armed.

4

L0 ready, waiting for L1

L0 finishes init and hands the machine to the default L1 entry declared via OC_L1_APP_DECL: ush in ring 3. The launcher prints l1 launcher: booting 'ush' (ring 3, 18968 bytes) and the boot task parks in a scheduler yield loop - there is no interactive kernel shell.

5

ush> - or an honest halt

The ring-3 world comes up: 274 registry apps plus 11 built-ins. If ush exits or fails to start, L0 does not pretend: it logs l1 launcher: default L1 app exited; L0 halting and parks in the halt loop - the honest guidance is a reboot or the OCBL boot menu. The 2.x oc> recovery fallback was removed in WP-03.

Every release gates on this exact sequence booting clean in QEMU twice - legacy BIOS and UEFI (OVMF).

The L1 program world

Everything users actually touch is a ring-3 program under src/L1/ - the shell included. One command = one app = one folder.

ush

The only shell

ush is the default boot entry: 274 registry apps served by name, 11 built-ins (cd, export, alias, jobs, history, ...), pipes, redirection, wildcards, environment - everything a daily shell needs, all in ring 3.

tui

The TUI desktop - an L1 citizen

Desktop, taskbar, menus, form widgets, a full-screen editor and the system apps live under src/L1/ and draw through the L1SVC tui service (services/tui). The 2.x layout with tui/ inside L0 is gone since WP-04.

cjk

Chinese console + IME

The CJK layer - 16x16 bitmap font, GB2312/UTF-8 codecs and the interactive pinyin IME - is a ring-3 program family under src/L1/ (chinese/, chinesetest/), riding the display/encoding/font services.

solib

Shared objects

An in-tree ld.so with dlsym and PIE relocations serves the dynamic-linking programs; the solib loader rides the l1 service category.

The L1SVC surface - 20 services / 190 numbered entries

SYS_L1SVC(110): one syscall routes a ring-3 call to the owning L0 service by category; the folder under services/ is the category. Ops are plain ASCII text renderers - the ring-3 side formats nothing. Renumber only by appending (src/L0/services/sysapi/l1svc_defs.h).

Reliability mechanisms

A service kernel is only credible if it can survive its own failures - these are the mechanisms, all reachable from ring 3 (ush>) through the L1SVC surface.

dump

Crash dumps

Register dump to serial on exception; crashlog persisted to the /etc volume; crashlog replays the last failures after a reboot.

wdt

Hardware watchdogs

Intel TCO and ACPI WDAT timers, armed for real - the E2E suite proves a hard reset and a clean second boot. Policy watchdogs kill starving tasks first.

klog

Kernel log

Ring buffer with levels and filters, generation-rotated files (kernel.log, kernel.log.1), dmesg served to ring 3 through the klog service.

health

Health monitoring

CPU / memory / task / IO sampling with alarms (CPU-LOCKED at 90%+), JSON export through the L1 surface.

Cross-platform build

One tree, three architectures, two host OSes - and it is reproducible.

make

make all, one command

Kernel, ISO, deterministic source zip and OTA package from a clean tree - tools/build.sh detects or installs the toolchain, build.ps1 covers Windows (WSL2 / MSYS2).

repro

Reproducible by design

SOURCE_DATE_EPOCH-driven archives; the same commit rebuilds the same bytes - the CI pipeline gates every push on it.

cross

ARM64 + RISC-V cross targets

Real bare-metal bring-up shells (PL011 / NS16550A serial, CNTPCT / CLINT timers) that print the banner and heartbeat in QEMU - same tree, different arch.

config

Fast and configurable

Content-addressed object cache (measured 3.2x on a warm build) and make menuconfig with defconfigs. The 2.x CONFIG_TUI / CONFIG_CHINESE switches are gone since WP-03 - the TUI and the Chinese layer are plain L1 programs now, always built into src/L1/.
